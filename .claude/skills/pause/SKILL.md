name: pause
description: Pause THIS session's WORK on the owner's order — let every in-flight builder run to its hand-back (never TaskStop it — a resumed agent re-writes its cache), bank each hand-back unverified and uncommitted, start nothing new, write the pause state into the working plan, tell the peers who are owed something, and keep the mail listener ON. `/pause --resume <in N minutes | at HH:MM>` also writes a resume work-order and arms it through /autorun (a bare `--resume` with no time means resume now, like `/pause resume`); without --resume the pause holds until the owner's resume signal. By default the pause keeps the cache warm for 12 hours from the pause, not just to the 5-hour reset, unless a due ping finds 5-hour usage at the limit (the gate skips it, since the API would refuse it, and the cache then usually goes cold) or a compaction comes first (a `/compact` stops it by design), only where keep-warm is switched on (the fleet switch or this session's pilot marker); `/pause --cold` lets the cache expire instead, for a pause the owner will not come back from soon. `/pause resume` verifies and commits each banked hand-back (and resumes a builder the owner had named to stop); `/pause status` reads the state. Owner-invoked. Distinct from /standby (the deaf park of the SEAT — listener off) and from /wrap (which persists). Use when the owner types `/pause`, says "pause the work / pause the agents", or later "resume" after a pause.

# /pause — hold the work, let the running agents finish, keep the seat awake, resume on a time or on the owner's word

The command grew out of a request to pause the work and the agents and have `/autorun` resume them at a set time, then to make that a `/pause` command whose `--resume` parameter takes the resume time and which, without it, holds until the owner's resume signal. The founding instance was run by hand: three builders stopped mid-fold, their state banked, a work-order written and committed, a one-shot `/autorun` armed, the hub told. This spec is that procedure, with the two things the hand run got wrong fixed: the fire time was first typed from expectation, and nothing on disk said the seat was paused.

⛔ **RUNNING SUB-AGENTS ARE NOT STOPPED — the pause waits them out to completion while holding everything else.** A `TaskStop` + later `SendMessage` resume re-sends the agent's whole context as a fresh cache write; letting it finish costs the remainder of a run already paid for, plus one turn of this seat per hand-back (a full re-cache of this seat's context when it lands after that cache has expired; the default keep-warm window of step 6b avoids that, and `--cold` gives it up). So the pause holds the SEAT's own work — no new dispatch, no fold, no gate run, no commit of any kind (§ While paused) — and every builder already running finishes and hands back; the hand-back is BANKED, not acted on. *(Step 1 once read "Stop every in-flight builder with `TaskStop`" and the resume re-sent each one by its banked id; the founding instance did exactly that to three builders.)*

## The state — what a pause is, and what it is not

| | `/pause` | `/standby` | `/wrap` |
|---|---|---|---|
| the WORK (new dispatches, folds, gates, commits) | **held**; builders already running finish and hand back, the hand-back is banked | untouched | finished for now |
| the mail listener | **on** — inbound is read and dispositioned | off — deaf | on |
| the owner's unrelated asks | **answered** (the pause is on the work, not the seat) | the next message auto-resumes | answered |
| what persists | the plan block + the banked builder state (+ a work-order when timed) | nothing | everything (`/meta learn`, memory, commits) |
| how it ends | the armed `/autorun` fires, or the owner's resume signal | the owner's next message | — |

**Marker:** `.claude/state/session-pause-<sid8>` — one line, `<epoch> <HEAD-sha> resume=<ISO-UTC | owner> wo=<plans path | none> builders=<scratchpad path | none>`. Written on enter, removed on resume. Today this skill, `/post-compact` (a recovery that finds it keeps the pause) and the keep-warm gate (`.claude/hooks/keep-warm-gate.py`, which passes pings only inside the 6b window while it exists) read it; peers see the plan block, not a badge — see Revisit.

**When the command lands:** a `/pause` typed while a turn is running is queued by the harness and reaches the seat only when that turn ends — a plain-text note is absorbed into the running turn within about 20 seconds, a slash command is not, and only Esc stops a running turn. So a seat never reads "the owner typed /pause" into its own in-flight turn: the pause starts when the command arrives, and what the turn did in the gap (dispatches, commits, mail) happened before the pause, not in breach of it; step 6 still resolves `<when>` against the time the owner TYPED it, which is the queued record's own stamp — the `timestamp` of the owner's record in the session transcript (a `queued_command` attachment with `origin.kind` human, or a user record with `promptSource` queued), while the landing time is the stamp of the turn that first reads it. If that time is already past when the command lands (a `--resume 15m` typed 20 minutes before it arrived; the longest gap measured below is 20 min 39 s), arm the one-shot for the next off-minute and say in the readout that the fire time moved and why. Measured four times in one transcript review: 2026-10-09 18:36:57Z typed and 18:57:36Z landed, nine readers dispatched in the gap; 23:31:26Z to 23:36:06Z; 2026-10-11 12:05:24Z to 12:09:29Z; 12:52:31Z to 13:03:49Z, with two commits, a hub mail and a reader dispatch in the gap.

## Process — `/pause [--resume <when>] [--cold]` (enter)

0. **Preconditions — stated, not asked.** `ListAgents` + the dispatch log (`.claude/logs/subagent-dispatch.jsonl`, rows for this session since the last dispatch you remember) give the in-flight builders — the log, not recall; a builder dispatched before a compaction is not in memory. `CronList` for an already-armed `/autorun` (a second one would double-resume). Background SHELLS (a full integration tier, an e2e run) are NOT stopped — they are cheap to let finish and expensive to restart — unless the owner names them; say which ones keep running. If `.claude/state/review-hub-active-<sid8>` exists you are the review hub: a paused hub still reads mail, so no broadcast is owed, but say so in the readout.
1. **Leave every in-flight builder RUNNING — no `TaskStop`** (above). Write one scratchpad file, `<topic>-paused-builders.txt`: one row per builder — name · agent type · agent id · its brief's path · the files its brief named · the verdict store file and patch it is folding · `still running` or, if it has already handed back, the hand-back's last line. ⛔ The agent ids never appear in owner-facing text or in a committed file; the scratchpad is session-private and uncommitted, which is why it is the home. A builder the owner NAMES to stop is the one exception: bank first, `TaskStop` second — the kill notification carries its last line, the resume cue.
2. **Measure what is on disk NOW.** `git diff --numstat` on every file a banked builder has already touched, and one content key per builder (`grep -cF '<a line only its edit holds>' <file>`), written into the same scratchpad file. The resume compares against these: an edit a peer's commit swept in the meantime reads as absent in the worktree and present in `git show HEAD:<file>`. A still-running builder's files move after this read — say so in the row; the hand-back's own summary is the reading that counts for it.
3. **Working plan — one dated `OWNER PAUSE` block, outside the SUMMARY-SYNC fence:** the owner's words verbatim; HEAD and this seat's commits since the last readout; each running builder with what it is building and the files it holds; everything designed-but-unwritten (a fix whose script aborted before writing, a brief composed but not dispatched); the pending gates and their last reading; the RESUME ORDER as a numbered list; the risk sentence (a peer's commit can sweep uncommitted builder edits). Flip the live-items row to `⏸ OWNER PAUSE <UTC>`. ⛔ Every timestamp in the block is DERIVED (`date -u`, a mail file's `created:`, `git log --format=%ct | date -u -r`), never typed; the founding run typed three and two were wrong by up to 14 minutes.
4. **Tell the peers who are owed:** the review hub (which of this seat's commits it holds, what will follow and roughly when, that nothing else arrives meanwhile), and any peer awaiting an answer from this seat. One mail each, through `session-manifest.py mail-send`, body by quoted heredoc, read back from the store file.
5. **Write the marker** (`echo "<epoch> <HEAD> resume=… wo=… builders=…" > .claude/state/session-pause-<sid8>`), after steps 1-4 — and, with `--resume`, after step 6's work-order commit and `CronCreate`, so that the marker is the LAST write of the ceremony and no commit of this seat's post-dates it (step 6 once ran after the marker, so every timed pause made a commit § While paused forbids). A recovery that reads it then finds the state it names, `wo=` included.
6. **With `--resume <when>`** (a time after the flag; a bare `--resume` is the resume signal, § Process — `/pause resume`): write `plans/wo-<topic>-resume-<YYYY-MM-DD>.md` — self-contained, per the `/autorun` template: what · why · the banked reconnaissance (HEAD, the commits, the builders file by PATH, the unwritten work with its settled design, the gate readings, where the hub's patches are) · the Approach in the plan's resume order (verify and commit the banked hand-backs, resume any owner-named stopped builder → land the unwritten work → the queued rounds → the closing sequence) · verification · the guardrails (never push, commit local through `safe-commit.sh`, no paid calls, builders never run git or the integration runner, ≤ N builders in flight, stop on a contested file) · a line-anchored completion marker (`^WO DONE `) whose prose mention cannot self-match. Commit it (explicit pathspec). Then the `/autorun` procedure: `date -u` FRESH, resolve `<when>` against the owner's "now" (the time of the owner's message, not the time you finish the ceremony), an off-minute unless the owner named the exact time, `CronCreate` one-shot in LOCAL time, `CronList` to verify before saying "armed". The cron prompt names the work-order path, the precondition gate (`grep -n '^WO DONE '`, the contested-file check, the listener check) and the guardrails. Say that the one-shot lives only while this terminal stays open.
6b. **Keep the cache warm — the DEFAULT; skipped only with `--cold`** (this step once ran only with `--keep-warm`, which is still accepted and changes nothing). This step needs the keep-warm skill and its gate hook (`.claude/hooks/keep-warm-gate.py`); without them it does nothing, so skip it. With `--cold`: remove any window file an earlier pause left (`rm -f .claude/state/keep-warm-pause-<sid8>` — the gate cannot tell a leftover window from a fresh one, and a leftover that has not ended passes pings through this pause), write no window file, and say in the readout that the cache will expire and the first turn after the resume re-caches the whole context. ⛔ First, if neither `.claude/state/keep-warm-enabled` nor `.claude/state/keep-warm-pilot-<sid8>` exists, say keep-warm is not switched on for this session, write no window file, and skip the rest of 6b: the gate blocks every fire before it reads the pause window, so the readout below would be false. ⛔ Likewise if `.claude/state/keep-warm-off-<sid8>` exists: the owner turned keep-warm off for this session, and the default must not undo that — `/keep-warm on` below deletes that marker — so write no window file, say keep-warm stays off as the owner set it, and treat the pause as `--cold` (the `/standby resume` step 2b check). Otherwise write `now + 12h` as one epoch to `.claude/state/keep-warm-pause-<sid8>` — the keep-warm runs for several hours regardless of the session limit hit or reset (the stop rule outside a pause already spans ~12 h, so that half needed no change). *(Until 2026-10-11 the window ended at the 5-hour usage reset, read from `five_hour_resets_at` in the status-line file, so the cache stayed warm until the rate-limit timer expired without running into the limit; a pause taken for some other reason then went cold a couple of hours in.)* Leave the `[keep-warm]` timer armed (`CronList`; run `/keep-warm on` if none is listed). While the window is open the keep-warm gate passes due pings past its stop rule (`STOP_PINGS` in `.claude/hooks/keep-warm-gate.py`), still blocks at the 5-hour limit (100%; the 95% ceiling was removed 2026-10-10), and stops by itself 12 hours after the pause. ⚠️ A ping skipped at the limit is usually the end of the warmth, not a gap: passed pings run 45 minutes apart, so the skipped one was the cache's last due fire that hour, the next fire finds it under a minute from expiry or expired, and the gate then blocks every fire to the window's end rather than pay a full re-cache. So say the end time as "until <time>, unless 5-hour usage reaches the limit first". A pause with no window file (`--cold`, keep-warm not switched on or turned off for this session, or a window that has ended) blocks every ping. Readout: say until when the cache is being kept warm, or that it is cold and why. ⛔ **And a compaction stops the warmth, by design: after ANY `/compact` (with or without `--disarm`), and after an automatic compaction (a ping at the compact point can cause one, `/keep-warm`), the gate refuses every ping while the post-compact recovery is pending. The recovery runs on the owner's next message or on whatever wakes the seat first — a `--resume` one-shot, or, without `--disarm`, a peer's mail the still-armed listener delivers — and after it an unexpired window passes pings again. So the end time is "until <time>, or until a compaction if one comes first", and a readout that hands the owner `/compact` as the next move says keep-warm stops there — never a clock time past it.** The reason: a `/compact` puts the session on hold, and after it there is no context estimate until the next call is made, so keep-warm must not wake the session; it resumes on the owner's signal, possibly on another account or after the session limit resets. A `/compact` is also used to switch models, with or without `--disarm` on `/pre-compact`. *(Before this rule, readouts promised "warm until <time>" on seats about to compact, and every ping after the compaction was refused — 7+ times across 4 sessions.)*
7. **Readout, in the owner's register, one short block:** what is held, which builders are still running and will hand back on their own (names, not ids), what else keeps running, what is armed and when — or that the pause holds for the owner's word — until when the cache is kept warm (step 6b) or that it is cold, the one risk, and the session-alive condition, numbers as digits. No plan table: the pause does not change what the plan says, only when it moves.

## Fleet and compact forms — `/pause --fleet`, `/pause --compact`, `/pre-compact --fleet`, `/pre-compact --pause`

These are the commands that act on every session at once. The per-session forms are unchanged and `--fleet` is opt-in per command, so the per-session listener rule stands.

- **`/pause --compact [--disarm]`** — enter the pause as above (any `--resume`/`--cold` flags apply), then in the same turn run `/pre-compact` through the Skill tool, with `--disarm` only when the owner typed it and never with `--pause` (that would loop). `--disarm` means the same on both commands: without it the listener stays on through the compaction, so a peer's mail can wake the seat and run the recovery first. `--disarm` without `--compact` changes nothing on `/pause`: say so (no compaction follows to re-arm the listener). `/pre-compact --pause [--disarm]` is the same command typed from the other side: it runs `/pause --compact` with the same `--disarm`. On a seat already paused (its `session-pause-<sid8>` exists), enter nothing, since the pause holds as it is, and still run `/pre-compact` as above: the save is the half not yet done. The readout says the seat is paused, banked and ready for the owner's `/compact`, whether the listener is off, and that keep-warm stops at that `/compact` (step 6b). One command where the owner typed three.
- **`--fleet` on `/pause` or `/pre-compact`** — this seat runs the command itself without the flag, then sends ONE wake mail: `python3 scripts/session-manifest.py mail-send --to all --subject "fleet <verb>: owner-typed in <sid8>; your hook carries the command"`, body one line saying the same. The mail only WAKES idle seats through their listener; it carries no authority. Each other open session's prompt/tool hook (`.claude/hooks/fleet_verb.py`, called by `auto-precompact-trigger.py`) finds the owner's typed record in `.claude/logs/skill-invocations.jsonl` (source `user-prompt`, `--fleet` among the words before the cut below, under 10 minutes old, from another session, not older than the receiving session) and puts a `⏳ FLEET <VERB>` line in that seat's context; the seat runs the same command minus `--fleet` through the Skill tool, before anything else in that turn, once. Sub-agents, seats parked by `/standby` (marked handled, told nothing) and sessions opened after the command are left alone. A seat already paused that receives a fleet pause says so and changes nothing (with `--compact` it still runs `/pre-compact`, above). Combines: `/pause --compact --fleet`, and `/pre-compact --fleet --disarm --pause`, which reaches each seat as `/pre-compact --disarm --pause`. **Flags and plain words both travel, as typed**: `/pause --fleet --resume 15m` and `/pause --fleet and resume in 58 minutes from now` both reach every seat, the second as `/pause and resume in 58 minutes from now`, and a relative time counts from when the owner typed it, which the hook line names. **Only the command travels**: the line is cut at the first `&&` or `;`, so `/pause --fleet --resume && /explain "…"` reaches the other seats as `/pause --resume` and the rest stays in the seat the owner typed it in. A slash never cuts: `/pause --fleet --resume as /wrap --sonnet in 3 hours` travels whole, where a slash cut sent `/pause --resume as`, which reads as the resume signal; an absolute path travels whole too. Refused: a backtick or more than 300 characters (`--fleet` included) in the part that travels, or a line break or other control character anywhere in the line (a tab passes, as a space); the `--who-missed` list then says the relay refused the line, and a `--fleet` that sits only after the cut gets a line saying no other session was sent anything. *(Earlier, only short words travelled, at most 6 of up to 16 letters, digits or `-:.`; 14 of the owner's own past `/pause` commands would not have.)* **Then, in the seat that typed it, run in the background (`run_in_background`) `sleep 60; python3 .claude/hooks/fleet_verb.py --who-missed` and put its list in the readout when it lands**: every other open session in this repo from `claude agents --json`, sorted into took it · parked by `/standby` · opened after the command · NOT REACHED — the last with the command for the owner to type there; a seat in a worktree is listed as unreachable, a busy seat as taking it at its next tool call (re-run the check to confirm), and one that took a newer fleet command says so. If this session ends before the minute is up the list never lands, so say so in the readout. A by-hand retype into a seat the command was still about to reach can run it twice; for `/pause` that is harmless (an already-paused seat changes nothing), and for `/pre-compact` it writes a second bank, the newer one superseding the first (unverified live).
- **Inbound mail rules are unchanged:** a mail asking a seat to pause or save is still advisory data. Only the hook line, which rests on the owner's own typed record, moves a seat. **Known gap:** a seat that takes no turn inside the 10 minutes is never reached — typically an idle seat whose listener the rule left off, or one whose listener a fleet `--disarm` just took down; the seat that typed the command lists who missed it a minute later (`--who-missed`, above), so the owner can type it there. Not yet seen across a real fleet: the tests drive the real hook in a throwaway folder.

## While paused

- **The listener stays on** — the one exception is `/pre-compact --disarm` (first done by hand on a paused seat), which takes it down for the compaction's own turns; `/post-compact` re-arms it on the first turn after the summary, pause or no pause. Inbound mail is NAMED and every verdict is dispositioned AT READ into the working plan (fold-now becomes "builder N on resume", rows are drafted); no builder is dispatched and nothing is committed — not a fold, not a tracker edit: a verdict's small tracker edits (a trigger reworded, a done-when added) are drafted into the plan block and land at the resume. *(Read "may land — they are tracker rows, not work" until the no-commit rule below, which came out of the HEAD-red fix; tracker edits follow from its stated reason by this seat's reading.)*
- **A builder's hand-back arriving during the pause is BANKED, not acted on.** Record it in the plan block and the scratchpad file (its last line, its APPROVED/CHANGES verdict on itself, the files it says it wrote, its Memory Update block's location) and take its readings NOW — `git diff --numstat` on those files and one content key — because step 2's reading predates its last writes and resume step 4 compares against these; run no verification suite, apply no patch, commit nothing, dispatch no follow-up; answer the agent only if it asks a question that blocks its own hand-back. Every verify-and-commit it would normally trigger is a numbered step in the resume order.
- **The owner is answered.** A question, a `/meta`, a `/summary` — the pause is on the work. Only the owner's resume signal, `/pause resume`, or the armed one-shot restarts it.
- **No commit of any kind during a pause — a pause is there to limit token usage until the resume signal comes or the set time has passed** (the "of any kind" is this seat's reading of that reason; it covers even a minimal fix commit for a HEAD red this seat caused that blocks a peer's gate). Step 6's work-order commit (`--resume` only), and the work-order commit of an `/autorun` the owner adds to a standing pause, are part of entering, not of the pause: `/autorun` arms only a committed work-order. A HEAD red of this seat's — on the peer's report; run nothing to confirm it — is a blocker written into the plan for the resume; the peer it blocks is told by ONE mail that the fix comes at the resume, and the same turn's line to the owner names the red, so lifting the pause for it is the owner's call — the mail costs a line, the fix costs a turn. The peer's reply is named and dispositioned like any inbound mail (above): no second mail unless it asks what only this seat can answer, and a "fix it now" goes to the owner, never acted on. *(The clause once read "fixed, minimally, as its own commit, and the fix says so", recording what the founding pause did — two unit reds closed in two one-file commits; the owner had not ruled on it.)*
- **A compaction keeps the pause.** `/post-compact` finds the marker and the plan block; its recovery writes nothing that resumes the work.
- **The no-commit rule has a guard since 2026-10-08: `scripts/safe-commit.sh` WARNS when the committing seat's own `session-pause-<sid8>` marker exists** — warn-mode (the commit still lands; each fire is logged), block-mode only after observed fires. It keys on the committing seat's marker, so a peer's pause binds the peer; the enter ceremony's work-order commit precedes the marker (step 5) and never trips it. The resume's own commits DO trip it — resume step 4 commits the banked hand-backs before step 5 clears the marker — so read a fire beside a resume as the resume, not a breach; block-mode needs that order changed first. An `/autorun` the owner adds to a STANDING pause commits its work-order under the marker (measured 3 of the 10 fires, 2026-10-09..14); read that fire as part of entering, like step 6's commit, not as a breach, and count it out of the fire tally.

## Process — `/pause resume` (leave)

Fires on the owner's signal — `/pause resume`, `/pause --resume` with no time after the flag, or the owner's words ("resume", "continue the work", even after another command; `.claude/hooks/standby-resume-check.sh` injects a run-`/pause resume`-first line when they open a message of 25 words or fewer or end one of 12 or fewer, when "let's resume" or "let's continue" sits anywhere in one of 15 or fewer, or when "unpause", "pause is lifted", "lift the pause" or "end the pause" sits anywhere in one of 25 or fewer with no "until", "before", "once", "when", "if" or a negation right before it (a "the", "my", "i", "we" or "you" between still counts) — elsewhere in a message they still count, and nothing nets them) — or as the first step of the armed work-order when the one-shot fires. ⛔ A bare `--resume` is never a timed pause: 13 of 13 owner uses meant resume now, and the two seats that entered a pause instead (one guessing the limit reset) were corrected by the owner's next message, which asked to resume. The founding "if omitted the pause holds" (above) names the flag omitted, as the description reads it, not the time. On a seat with no pause marker, say there was nothing to resume and enter nothing.

0. **A seat parked by `/standby` after the pause resumes the SEAT first.** If `.claude/state/session-standby-<sid8>` exists, the owner parked this seat while its work was paused: run `/standby resume` (marker cleared, listener armed, inbox read) before anything below — a pause resume on a parked seat would otherwise arm a listener the standby spec says must stay off, and step 3's store sweep would double the `/mail check` that resume runs. Since 2026-10-08 an armed one-shot WAKES a parked seat too — `standby-resume-check.sh` classes its prompt as the owner's authorization and directs `/standby resume` first, then the one-shot's work — so this branch is reached by the owner's own resume or by the one-shot; until then the hook classed that prompt as a harness event and only the owner's message reached it. After `/standby resume`, step 3 below sweeps only the mail that its `/mail check` did not just disposition.
1. **One resume, not two.** If a `/autorun` one-shot is armed and the owner resumed by hand, `CronDelete` it now; if the one-shot fired, the marker and the plan block are the state it reads, nothing else.
2. **Re-arm the listener only if it is DEAD** — `kill -0 "$(cat .claude/state/mail-listen-<sid8>.pid)"` fails, or the Monitor's own expiry notice has arrived with no re-arm since. **A live pid is a live watch: do not arm a second Monitor beside it** — two listeners deliver every inbound mail twice, and the duplicate reads as a peer resend (measured once: a pid-file-keyed re-arm beside a Monitor with 18 minutes left). Dead ⇒ the Monitor tool, `timeout_ms: 1800000`.
3. **Store sweep:** every mail to this seat newer than the marker's epoch, read from the store files, dispositioned at read.
4. **Each banked builder, in the scratchpad file's order.** HANDED BACK (before or during the pause, not yet verified) → the ordinary post-hand-back path, now: `git status --short` + `git diff --numstat` on the files it named against the banked readings, the content key in the worktree AND in `git show HEAD:<file>`, then verify and commit per its brief (present and unchanged → verify as usual; absent in the worktree and present at HEAD → a peer's commit swept it in, verify at HEAD; absent in both → the edit was lost, re-brief a FRESH seat from the verdict). STILL RUNNING → nothing to do; it hands back on its own and takes the same path then. A builder the owner had NAMED to stop → `SendMessage` to its agent id: HEAD now, how its files read, "continue from your last line, hand back per the original brief", and the word `RESUME-OK` (`subagent-resume-guard.py` refuses a send to a helper idle past 4 minutes without it). A builder that DIED during the pause (an API limit, a logout, a revoked token — the hook names it) → `/limit-recovery`: its scan says BANKED, RESUME, WAIT or FRESH (resume, except a model change or a failed resume; WAIT for the reset when the agent's own model is at its limit, except a Fable agent at Fable's own limit, which is FRESH on Opus at once), never a blanket resume without the scan. ⛔ A `ListAgents` row is not the test — a stopped agent is absent from it and still resumable; the `SendMessage` result is the test.
5. **Clear the marker** (and `.claude/state/keep-warm-pause-<sid8>` if present — the keep-warm gate then returns to its normal rules), flip the plan row (`resumed <UTC> after Nh MMm; N hand-backs verified, S still running, R resumed, K re-briefed, M mails read`), continue the plan's resume order.

## Boundaries

- **Owner-invoked only** — typed here, or typed with `--fleet` in another session and delivered by this seat's `⏳ FLEET PAUSE` hook line (§ Fleet and compact forms). A seat never pauses its own work; a seat that has run out of work says so and keeps listening.
- **Not `/standby`:** standby parks the SEAT (deaf, nothing processed, the owner's next message wakes it); pause parks the WORK (nothing new starts, running builders finish and are banked, seat awake, owner's asks answered).
- **Not `/wrap`:** no `/meta learn`, no memory writes, no readout of the whole session — `/wrap --checkpoint` before a long pause is the owner's call; say so once in the readout if the session holds unpersisted decisions, never run it unasked.
- **Not a worktree or a stash.** Builder edits stay where they are, uncommitted in the shared tree; the risk is named, not engineered away (a stash is banned fleet-wide, and a commit of half a fold is worse than the risk).
- **`--resume` is the `/autorun` contract:** session-only, in-memory, fires only while this terminal is open and idle; it never pushes.
