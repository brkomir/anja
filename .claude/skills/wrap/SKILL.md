# Wrap — Session End

End-of-session checklist. Ensures nothing is left hanging and all decisions are persisted.

**The core, paid on every invocation and compaction carry.** Each step's full prior text (measurements, incidents, history, long commands) moved, with the copy's edits, to `references/full-text-{preamble,0-1,2-6,7,8-12}.md` under `## Step N`, beside the older notes those point to. This core wins a disagreement; **READ IT** marks a step whose full-text section holds an instrument it cannot run without. **Appending:** DIRECTIVE + TELL + the number the action needs go here, in the owning step (a new section is the last resort); the why goes to the reference in the SAME commit; a correction REPLACES the sentence; incidents never go into a step. A budget test holds the core to a byte ceiling.

## When to Use
End of every session, or when the user says "let's wrap up" / "that's it for now". **Not typed by the owner this turn** (after a recovery, or on an earlier "as recommended") ⇒ the first line quotes the owner's authorizing words with their time (a standing cadence the owner ratified, `review-hub/SKILL.md` § Checkpoint cadence, or the `/autorun` work-order the owner armed, counts: quote that) and names the model this runs on; no such words ⇒ do not start it.

**Checkpoint mode (`/wrap --checkpoint`; `/wrap checkpoint` is an accepted alias):** same steps, same rigor, the session CONTINUES. The summary frames as **"Checkpoint complete — session still live"**, NEVER "Session closed" (framing only; the marker is 'wrapped' either way). **A checkpoint ends by checking the mail listener** (after Step 12 when it runs): `kill -0 "$(cat .claude/state/mail-listen-<sid8>.pid)"` fails, or the Monitor's expiry notice arrived with no re-arm since ⇒ re-arm (`python3 scripts/session-manifest.py mail-listen --poll 30`, `timeout_ms: 1800000`; a review hub adds `--rebroadcast-hours 48`) unless `.claude/state/session-standby-<sid8>` exists. A review hub also checks its poller: `pgrep -P $PPID -f '[h]ub-stale-request-poll'` empty ⇒ re-arm it as a second Monitor (`timeout_ms: 1800000`, this session's newest arm command, filters included; `/pre-compact` Step 1 shows the read), same standby exception. A live pid is a live watch: never arm a second one. A review hub (`[ -f .claude/state/review-hub-active-<sid8> ]`) ⇒ before the readout, at a checkpoint and at a plain `/wrap` alike, write the digest (`review-hub/SKILL.md` § The digest) and check the self-review trigger (§ THE HUB REVIEWS EVERYONE).

**Light mode (`/wrap --light`).** ONE change: the Step 1b-DEEP slice target rises into the band below, cutting the AGENT COUNT. ⛔ **THE BAND IS ×3-×5 (6-10 MB), DEFAULT THE TOP — ×5 / 10 MB; a smaller multiplier ONLY when it yields the SAME N.** Per-agent spend ~89-108k tokens, FLAT in slice size. ⛔ **Price the mode on WHOLE-RUN tokens, main agent included, never agent count; the standing bar is light only when it is at least twice as token-efficient; state your denominators.** ⚠️ **STATE THE TRADE in the output whenever `--light` is active:** past ~2.4 MB an agent cannot context-read its slice — coverage rests on grep + windowed reads, UNMEASURED. The bigger lever is scoping to the last checkpoint; READ `references/modes-and-light-history.md` first (the checkpoint grep must exclude the current invocation).

**Memefy mode (`/wrap --memefy`).** The only way Step 10 runs (in the source project, a write-up suggestion this copy does not ship); combines with the other flags. Without it Step 10 is skipped in silence.

**Sonnet mode (`/wrap --sonnet`).** ONE change: the 1b-DEEP slice agents dispatch with `model: "sonnet"` instead of the default `model: "opus"` (`/deep-pass` § MODEL ROUTING: served-model read-back, one slice first, any launch serving anything but `claude-sonnet-5-5` ends dispatching — the undispatched region is declared unscanned and one question goes to the owner). **State it in the output, one line, with the served model per slice** — or *"--sonnet: no deep pass fired, no slice ran"* (`--light` never skips the deep pass). Both models are a preference, not a quality call; a later comparison runs both on one brief at one explicit effort. Without the flag the slices run on Opus whatever the session's model.

## The modes COMPOSE, and all three are FLAGS — `/wrap --checkpoint --light --sonnet`

Disjoint levers (how the run ENDS — `session-lifecycle.py` derives CHECKPOINT; how the deep pass is SLICED; which MODEL runs the slices), so they stack. **Nothing parses any of this:** read intent over spelling in BOTH directions; `/wrap checkpoint --light` and `/wrap --checkpoint --light` are one request, and neither spelling is worth a correction to the owner.

## Process

**⚠️ IRON LAW:** NO "complete" / "N/N steps ran" / "nothing hanging" claim without a COMPUTED artifact count for every ENUMERATION the summary asserts; a mandatory-fired step with no artifact is an INCOMPLETE wrap. The checkmark is a pasted command output + the Step-11 reconcile, never memory of intent. Red flags: *"the arc is in-context, the deep-pass is redundant"* (the trigger fired on a filesystem count — RUN it) · *"I persisted the high-value subset"* (a silent DROP unless each dropped block is a named dedupe with a `MEMORY:line`; state N emitted → M persisted) · *"10/10 steps ran"* (cite each step's ARTIFACT) · *"nothing hanging"* (run Step 11 BEFORE the summary) · *"Step N skips — I read the gate earlier"* (**a skip-gate reading goes stale inside the same wrap**: re-derive at the MOMENT of skipping, or just RUN it).

**Held review batch — send it NOW, before Step 0** (the coherent-batch rule's early-send case (c)): holding commits for a review ⇒ mail them all to the hub in ONE request, every sha with its refute claim; every step before the send is hub latency. Step 5e re-checks that it went.

**0. Session manifest write + prune (MANDATORY at /wrap start).** Run:

```bash
# GATE — MUST print a positive verdict; silence is NOT a pass
: "${CLAUDE_CODE_SESSION_ID:? GATE ABORT — session id unset, the gate cannot be evaluated}"
M=".claude/state/post-compact-pending-$CLAUDE_CODE_SESSION_ID"
C=".claude/state/post-compact-cleared-$CLAUDE_CODE_SESSION_ID"
if [ -f "$M" ]; then echo "🧠 MARKER PRESENT (sid=$CLAUDE_CODE_SESSION_ID): $(cat "$M")"
elif [ -f "$C" ]; then echo "⚠️  GATE UNINFORMATIVE (sid=$CLAUDE_CODE_SESSION_ID) — a recovery ran THIS session and cleared the marker at $(cat "$C"); this reading is not an independent check"
else echo "✅ GATE CLEAR (sid=$CLAUDE_CODE_SESSION_ID) — neither marker is present for THIS session (present tense: this cannot rule out a clear that left no breadcrumb)"; fi
python3 scripts/session-manifest.py write              # snapshot final session state
python3 scripts/session-manifest.py prune              # cleanup manifests stale >24h
python3 scripts/session-manifest.py mail-check --peek  # NON-consuming surface of mid-session inbound mail
python3 scripts/queued-directive-residue-scan.py       # rc 0 clean · 3 residue (READ IT) · 1 instrument failure
python3 scripts/orphaned-prompt-scan.py                # rc 0 clean · 3 residue (READ IT) · 1 instrument failure
python3 scripts/session-lifecycle.py wrapped           # WRAPPED marker · ⛔ IN CHECKPOINT MODE PASS THE FLAG: `… wrapped --checkpoint` (intent is DECLARED, never inferred)
```
Three gate branches on purpose: a bare CLEAR cannot tell "no marker" from "this session cleared one". A residue rc 3 is a WORKLIST you READ (`references/step0-gate-notes.md`).

**⛔ GATE — do NOT advance past Step 1 while `.claude/state/post-compact-pending-<sid>` exists.** Present ⇒ NAME it in your very next response and act first (the wrap the compaction cut then CONTINUES; post-compact Step 7's "no new `/wrap`" bars only a wrap not yet started, and re-invoking `/wrap` to reload its spec is this continuation): `focus=no` ⇒ `/post-compact`; `focus=yes` ⇒ **READ `focus_args` AND JUDGE IT — the flag alone sanctions nothing:** a CURATION of the cutoff (an argument naming a thread to keep) sanctions the skip, a DIRECTIVE in the slot (an instruction about what to do after the compaction) does not ⇒ run the recovery; name the decision and quote the argument either way. Then **`rm` the marker** (it tracks "recovery decision made"). ⛔ **ONE EXCEPTION, non-blocking: `python3 scripts/post-compact-deferral.py status --sid $CLAUDE_CODE_SESSION_ID` exiting 0 (`DEFERRED`) = the pre-compaction hook fired, no compaction landed; the marker stands — say "pre-compaction hook fired, no compaction landed yet", never "prepared", and continue.** Exit 1 (`OWED`) ⇒ `/post-compact`. ⛔ **An auto-compaction can write the marker MID-WRAP:** re-derive `[ -f ]` at the END of Step 0 too, and a post-compact directive in this turn's SessionStart output overrides a clear `[ -f ]` (PRESENT wins).

## Commit procedure (shared with /audit-check Post-Gate Action)

1. **Enumerate:** `git status --porcelain` (never `-uall`).
2. **Classify:** MINE (touched via Edit/Write/Bash this session — from conversation context) and SHARED MEMORY (`.claude/skills/*/MEMORY.md`, append-only) ⇒ include; PARALLEL (a concurrent session's) ⇒ exclude; UNKNOWN ⇒ ask the user before committing.
3. **Explicit file list:** `git add path/one path/two …`, MINE + SHARED MEMORY only; **never** `git add -A` / `.` / `-u` with parallel sessions active. **Pre-stage check:** `git diff --staged --name-only` first — foreign staged files ⇒ **use `scripts/safe-commit.sh`** (its gates run in the SAME PROCESS as the commit). If it REFUSES on a peer's foreign staged path: do not unstage, do not commit bare, **do not HOLD** (the worst option): gate both numstat columns by hand, commit, and say in the body that you did (`.claude/rules/bash-environment.md`).
4. **Message:** `/audit-check` post-PASS `{scope}({feature-id}): {COMPLETE summary}`; `/wrap` hygiene `{session-subject}: {one-line summary}`; never a sensitive file.
5. **Hook failure:** fix, re-stage the same files, NEW commit — never `--amend`; `--no-verify` only on the user's explicit request.
6. **Skip:** empty list ⇒ silent, no empty commits.
7. **Proactive visibility layer (HIGH overlap ONLY):** this wrap committed a shared meta/memory file a peer also committed or staged DURING the wrap, or ≥2 peer commits landed on `main` since your session-start SHA ⇒ READ `references/conditional-step-bodies.md` § Commit procedure 7 and fire the announce.

## Output

Per the Iron Law + Step 11: every `{N}` below is a PASTED command output; the `Wrap-verification` line is the computed completion proof — a wrap that cannot emit it is not complete. **`Bottom line:` FIRST, REQUIRED:** plain words only (no coined name as its subject, no unit-bearing number, closure token, sha, path or rule id — words the OWNER uses); never manufacture a claim to fill it — if closing costs nothing, say so; a sent review whose verdict has not arrived IS a cost (the closability row, `.claude/orchestrator/conventions.md`).
