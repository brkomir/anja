Owner-invoked; distinct from /wrap (which keeps the listener armed) and from exit (the process and its work stay). # /standby — park this session until the owner speaks

The command is for a session that is held open but should not wake on mail turns, so it spends no tokens, and is resumed by hand when needed. Standby shuts the mail listener down, so nothing external wakes the session except the owner's next message. It is a state of its own, and it is what peers see when they check whether the session is still active. On resume the state is updated, the listener re-armed, pending mail read, and the owner's message answered.

## The state — why a marker and not a flag on the listener

Three lifecycle states existed: `ACTIVE`, `WRAPPED` / `CHECKPOINT` (done-for-now, STILL receives mail), `EXITED` (terminal). None said *alive, holding its work, deliberately deaf* — and the gap had a measured cost: two standing directives (the SessionStart arm line and post-compact Step 5) re-armed a hand-disarmed listener at the next resume or compaction, silently undoing the park. So the state is a marker every consumer reads, derived by the lifecycle SSOT (`scripts/session_status.py`) as `STANDBY`:

`.claude/state/session-standby-<sid8>` — body `<epoch> <HEAD-sha>` — written by `session-lifecycle.py standby`, removed by `session-lifecycle.py resume`.

**Who reads it.** `who` / `/peers`, `read`, the overlap gate, `hub-discover`, `parallel-session-scan.py` and `/whoami` render `⏸ standby` with the words *listener disarmed, mail queues until the owner resumes it*; `mail-send --to <you>` warns the sender; `session-start.sh` prints the STANDBY line and does NOT emit the arm directive; `mail-listen-arm-reminder.sh` stays silent; `/post-compact` Step 5 leaves the dead listener alone; `standby-resume-check.sh` (UserPromptSubmit) injects the resume directive on every prompt until the marker is cleared — the same persistent-net shape as the post-compact marker, because a one-shot line can be lost behind a compaction and a per-prompt net cannot.

**Ordering.** `EXITED` wins (a parked seat can still die). `STANDBY` beats `WRAPPED` / `CHECKPOINT` in either marker order — the marker is the state, exactly as the three hooks read it; the wrap marker stays on disk for `mail-await --peer-done`. A transcript record does NOT demote it: the owner's own message is a record, and the marker must outlive it until `resume` clears it. The seat stays IN the overlap gate (it holds uncommitted work). The marker ages out at 30 days (`STANDBY_GC_DAYS`, `session-lifecycle.py`); past that the seat reads `ACTIVE` and re-arms through the standard path on the owner's next message.

## Process — `/standby [--resume <when>]` (enter)

0. **Preconditions — stated, not asked.** `ListAgents`: a running sub-agent's completion notification will wake this session; say so and continue — standby never aborts an in-flight agent. `CronList`: an armed `/autorun` one-shot WAKES a parked seat: `standby-resume-check.sh` classes its prompt (`[Owner-authorized …`) as the owner's own authorization and directs `/standby resume` first, then the one-shot's instructions — say which one is armed and when it fires, so the owner can cancel or keep it. (Before the hook classed that prompt as the owner's authorization it treated it as a harness event and the parked seat ignored it, so a park under a go-ahead armed nothing and the work waited for the owner's next message.) `TaskList`: every OTHER persistent Monitor still wakes this seat; stop it in step 1 or name it here. If `.claude/state/review-hub-active-<sid8>` exists you are the review hub, and a parked hub is a deaf hub: send ONE broadcast first — `python3 scripts/session-manifest.py mail-send --to all --subject "review-hub <sid8> STANDBY — delegations queue until the owner resumes it"` — the *say plainly this inbox is now poll-only* exit that `review-hub/SKILL.md` § `/review-hub --retire`, step 5, requires.
1. **Stop the listener.** `TaskStop` the Monitor task you armed (its id is in the arm result). If the id is gone — a compaction ate it — kill the process instead: `kill "$(cat .claude/state/mail-listen-<sid8>.pid)"`, then confirm `kill -0` on that pid FAILS. Either way: `rm -f .claude/state/mail-listen-<sid8>.pid .claude/state/mail-listen-armed-<sid8>`. **On the review hub, also `TaskStop` the staleness poller** — a parked hub's requests all go stale, so a live poller wakes it on every one. ⛔ **Removing the armed marker is load-bearing:** it is what makes `mail-listen-arm-reminder.sh` a live backstop again after a resume that forgets step 2 below.
1b. **Stop the keep-warm timer too.** `CronList`, then `CronDelete` every job whose prompt starts `[keep-warm]`, then `rm -f .claude/state/keep-warm-armed-<sid8>` — left in place it silences `keep-warm-arm-reminder.sh` after the resume, so a missed step 2b leaves the seat with no timer and no reminder. The gate already blocks every fire while the standby marker exists (`keep-warm-gate.py`), so the cache is let go either way; deleting the job is what stops a "blocked by hook" line printing at every tick of a parked seat. Do NOT write `keep-warm-off-<sid8>` — that is the owner's off, and resume reads it.
1c. **With `--resume <when>` (the same parameter `/pause` carries):** arm the wake-up as an `/autorun` one-shot. `date -u` FRESH, resolve `<when>` against the owner's "now" (the time of the owner's message), an off-minute unless the owner named the exact time, `CronCreate` one-shot in LOCAL time with a prompt that opens `[Owner-authorized autonomous run — one-shot cron fired ~<TIME> <DATE>, the timed wake of the /standby of <UTC>]` and says: run `/standby resume` first (the hook's directive on that prompt says the same), then continue what the park interrupted — name it in the prompt (the work-order path, or the plan's Closability STANDBY line's "what runs when it does"). `CronList` to verify before saying "armed". Say that the one-shot lives only while this terminal stays open. Without `--resume`, or with no time after it, the park holds for the owner's word, as before. On a seat already parked, a bare `--resume` is the owner's wake message: run `/standby resume` and enter nothing (the `/pause` reading, where 13 of 13 bare uses meant resume now).
2. **Stamp the state.** `python3 scripts/session-lifecycle.py standby` → `marked STANDBY (<sid8>)`. Confirm: `python3 scripts/session-lifecycle.py status` prints `STANDBY`.
3. **Working plan.** One line under Closability: `STANDBY since <UTC> — listener stopped, marker stamped; nothing wakes this seat but the owner's message` — or, with `--resume`, `… or the one-shot armed for <UTC>`. The plan is updated AT the state change.
4. **Say it, one short paragraph, in the owner's register:** what stopped, what peers now see, that only the owner's message wakes you, what runs when it does — and anything from step 0 that will still fire. If the session holds decisions nothing has persisted and the park may be long, say in that paragraph that `/wrap --checkpoint` first is the owner's call; do not run it unasked.

**Standby persists NOTHING on purpose** — no summary, no `/meta learn`, no memory write, no commit, no mail beyond the hub broadcast. It is the cheap park; `/wrap` is the expensive one.

## Process — `/standby resume` (leave)

Fires on the owner's next message: `standby-resume-check.sh` injects the directive on that prompt (and `session-start.sh` prints it after a compaction or a `--resume`). **The owner's message is answered LAST — after the seat can hear again.**

1. `python3 scripts/session-lifecycle.py resume` → `STANDBY cleared (<sid8>) — parked Nh MMm`. The marker peers read is gone from here.
2. **Re-arm:** Monitor tool, `timeout_ms: 1800000`, running `python3 scripts/session-manifest.py mail-listen --poll 30` — **on the review hub `--rebroadcast-hours 48`, plus the staleness poller** with this session's newest poller arm command, its filters included (`/pre-compact` Step 1 shows how to read it), else `review-hub/SKILL.md` Phase 1's loop; the directive names both. The PostToolUse marker hook rewrites `mail-listen-armed-<sid8>`, so the arm-reminder stays quiet. Skip this step when `printenv SKIP_MAIL_LISTEN_ARM_REMINDER` prints `1`: a setup that never runs two sessions at once switched the listener off, so leave it off and say so in step 5's resume line.
2b. **Re-arm keep-warm** when it applies to this seat — `.claude/state/keep-warm-enabled` or `.claude/state/keep-warm-pilot-<sid8>` exists and `.claude/state/keep-warm-off-<sid8>` does not: run `/keep-warm on` (it confirms the hooks are wired and never arms a second job). Otherwise skip silently.
3. **`/mail check`** — the Skill, so the advisory block and the inbound discipline apply: NAME each inbound, VERIFY its state claims against git or the tracker before relaying, disposition every verdict AT READ (fold now / tracker row now / named reject). Broadcasts count. A verdict that arrived during the park is exactly the mail this state exists to queue, so the read is not optional.
4. **Working plan:** flip the STANDBY line to `resumed <UTC> after Nh MMm; N mails read (K verdicts dispositioned)`.
5. **Answer the owner's message in the same turn.** Open with one line — *resumed after Nh MMm, N mails read, listener armed* (*listener switched off* when step 2 was skipped) — then the answer. The reply's marker is whatever the owner's message invokes (`[main]` for plain text, the command's name if the owner typed one); the resume line sits under it.

⛔ **If the prompt that fired the directive is NOT the owner** — a task or monitor notification — do nothing: leave the marker, stay parked. **An `/autorun` one-shot's prompt (`[Owner-authorized …`) IS the owner's: it carries the owner's authorization, so it ends the park exactly like the owner's message — resume first, then run what the prompt says.** In standby there are no listener turns, so this is rare; the guard exists because a UserPromptSubmit also fires on notification turns.

⛔ **A compaction on the resume turn** — the owner's message itself overflows the context, measured on this command's founding session (2026-09-23 15:45Z) — is handled in this order: `/post-compact` first (its Step 5 sees the marker and leaves the listener alone), then `/standby resume`, then the answer.

## Boundaries

- **Owner-invoked only.** A seat never parks itself: the rule for a seat that has stopped working is to STOP the listener and SAY so; the park is the owner's word, and so is the resume.
- **Not `/wrap`:** a wrap persists and keeps listening; standby persists nothing and stops listening. **Not exit:** the process stays up, the work stays held, the overlap gate still counts the seat.
- **Survives a terminal close.** `session-end.sh` leaves the marker alone, so a parked seat closed with the window and later `--resume`d is still parked until the owner's message clears it (EXITED speaks only until the seat takes a turn, then STANDBY speaks again).
- **Read-only state-query for peers:** they see the badge; nothing they send changes the state. Only the owner's message to THIS seat does.

## Revisit

- A parked seat found re-armed with its marker still present means a re-arm path was missed: `rg -n -i 're-?arm|mail-listen --poll' .claude/hooks/ .claude/skills/ .claude/orchestrator/` and check each directive carries the standby guard — key on the ACT, not the command literal: `conventions.md`'s *re-arm if dead* clause never names the command.
- If the owner routinely `/wrap --checkpoint`s before parking, add a `--checkpoint` flag that runs the wrap first.
- If a park ever exceeds 30 days, raise `STANDBY_GC_DAYS`.

**Marker:** `[standby]` on the enter turn. The resume turn carries the marker of whatever the owner's message invoked.
