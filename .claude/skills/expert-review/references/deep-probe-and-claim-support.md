## 7a-ii Lead-Directed Deep Probe — qualification, agents, brief, guards, SC-3 revisit — from `SKILL.md` § Process

   - **Lead qualifies if** `([SINGLE-SOURCE] ≥P1  OR  any P0  OR  cross-seam/sibling-family flag  OR  "test looks thin" flag)` **AND has a readable oracle** (code / migration / runtime state / vendor doc) **AND is not cheaply orchestrator-traceable** (spans a multi-file subsystem / vendor behavior / adjacent surfaces). **EXCLUDE pure-judgment leads with no ground truth to read** — there a fresh agent anchors and rationalizes (Huang 2024: *intrinsic* self-correction degrades; grounding in source is the *verifier* direction, which does not). For a singleton, voting is useless — there is no second voter — so grounding SUBSTITUTES for corroboration; singletons are disproportionately the real, non-obvious bugs, and this is the only mechanism that resolves their confidence.
   - **Agents:** 1 fresh-context agent per lead, **hard cap 3-4** (inherits 7a's cap). NEW launch of the domain-matched expert — NOT the pass-1 author (avoids self-correction frame), NOT the orchestrator (avoids saturated context), builder≠breaker. `>4` qualifying leads is ITSELF the finding: pass-1 was too shallow — surface it, do not fan out further.
   - **Brief (load-bearing — feed the lead as a COORDINATE, not a conclusion):** *"Pass-1 flagged {area} on shallow evidence; the reason is WITHHELD. Fresh budget. (1) GROUND-OR-KILL: read the actual code/state — CONFIRM with file:line + mechanism, OR REFUTE; refutations are valued EQUALLY. (2) ADJACENT SWEEP, **bounded to the same file / function / seam / data-flow** as the lead: find the deeper bug the shallow pass missed; do NOT re-audit unrelated surface. 'Investigated, no bug — here is the file:line proof' is a VALUED result."* The verdict is stripped to a coordinate (this OPERATIONALIZES the *directions, not conclusions* rule rather than violating it). **Abstention-allowed is mandatory** or the must-find pathology manufactures false positives. One level only — adjacent findings are tagged `[SINGLE-SOURCE]` and are NOT recursively re-probed.
   - **Anti-anchoring guards (reuse existing):** the verdict-flip-needs-new-evidence gate + factual-claim verification apply to the diver's output — a confirm with no oracle evidence is discounted exactly like a kill with none.
   - **Default verify is still the orchestrator code-trace** (an earlier experiment's ~0-cost winner): trace findings inline FIRST; spawn 7a-ii divers only for the genuine fresh-deep-context residue that a budget-saturated orchestrator cannot reach.
   - **NOT a rejected pattern:** no redundant broad re-runs (≠ Multi-Run Union — its N>3 cliff is about *votes*, not *depth*) and no peer-visibility / position-updating (≠ debate-rounds — zero sycophancy surface). It is the anti-debate: solo grounded investigators. Cost ≈ **+25-50% on a final-audit** (3-4 × ~25k); excluded everywhere else.
   - **SC-3 revisit (mandatory — this is N=1-structural, not frequency-proven on our codebase):** after the first final-audits run 7a-ii — if no diver KILLED a single-source flag OR surfaced an adjacent bug across 3 audits → anchoring dominates, downgrade to confirm-only. If `>4` leads routinely qualify → pass-1 depth is the real gap, fix THAT instead. If a diver catches a P0 the orchestrator-trace structurally could not → promote toward default for high-stakes.

## 7a-iii Claim-support pass — agent, verdicts, controls, gate, weakness, cost, SC-3 run record — from `SKILL.md` § Process

   - **Agent:** ONE, `general-purpose`, **no expert skill loaded — the skill-lessness is the mechanism, not a saving.** A domain lens shares the panel's frame and is the wrong instrument for auditing a conclusion drawn inside that frame; a reader with no domain has nothing to be captured by and only has to ask whether the evidence gets you to the claim. Brief it OFF the panel's own record — the process log where 7b wrote one; on a panel under seven lenses 7b writes none, so write the annotated claim list to the plan file first and brief it off that. **Grounding gate (7a has it; this step lacked it until 2026-09-21): a verdict that cites no artifact — file and line, a commit, a measured output — is discarded whatever it says.**
   - **Verdicts — FOUR, and the third is the point:** CONFIRMED · REFUTED · **OVERREACH** (facts hold, conclusion is wider than they carry — state the narrower claim the evidence does support) · UNVERIFIABLE (say what would settle it). Without a distinct OVERREACH verdict the class collapses into REFUTED and the useful half of the answer is lost.
   - ⛔ **SEED IT WITH CONTROLS OF BOTH POLARITIES, UNLABELLED, EACH WITH ITS EXPECTED VERDICT WRITTEN DOWN BEFORE DISPATCH — AND DISCARD ON EXPECTED-NOT-EQUAL-RETURNED, NEVER ON "IT KILLED A CONTROL".** Its confirmations are worth nothing until you know it can discriminate — a validator that confirms everything reads exactly like a validator that is working, and a positive-only control set is passed perfectly by exactly that validator. So beside the true claims you re-derived, plant at least one OVERREACH you have already narrowed (expected OVERREACH) and one FALSE CONCLUSION you have already closed (expected REFUTED or OVERREACH — a two-valued expectation, so the record must be able to express one). The gate sits on the DOWNSTREAM DISPATCH, not on reading: one return arrives whole, so score the controls first and only then let the other verdicts drive a fold or an owner line. *(Until 2026-09-21 this read "controls you have ALREADY VERIFIED … if it kills one of those, discard the run" — positives only, a rule that would have discarded the second run recorded below, which planted two negatives and thereby proved the instrument.)*
   - **Gate on FINDINGS THAT REACH THE OWNER, not on panel size.** The compression step is where this failure lives and the owner's attention is what it costs. A twelve-lens panel whose findings stay internal needs it less than a three-lens panel whose one finding goes in front of the owner.
   - ⛔ **WHAT IT IS MEASURED BAD AT, so nobody reads a REFUTED as final: IMPLICIT SCOPING.** A claim true of a narrow population and false of a broad one gets REFUTED when the honest verdict is *unresolved* — the validator does not know the architecture well enough to see that the panel meant the narrow reading. **Treat every REFUTED on a scoping question as a prompt to re-derive, not as a verdict.** Measured: it refuted a per-zone claim by checking the global question, and the narrow claim survived a re-check.
   - **Cost:** one agent, ~25% of one lens. Cheap enough that the argument against it is ceremony, not budget.
   - **SC-3 revisit (mandatory — N=2-structural, not frequency-proven, same standing as 7a-ii):** FOUR runs so far, each recorded in its process log. A nine-lens feature audit (2026-09-19): 10 claims, 4 true controls CONFIRMED and the known overreach returned OVERREACH — 5 of 5 as expected; it refuted one claim and killed one number (the ~30 KB aggregate, a figure that reproduced at no denominator), and its REFUTED was a scope question the orchestrator had compressed — the IMPLICIT SCOPING weakness above. A second feature audit (2026-09-20): 18 items, 5 unlabelled controls — 3 true controls CONFIRMED, a planted OVERREACH returned OVERREACH, a planted FALSE CONCLUSION returned REFUTED — 5 of 5 scored as expected, which is NOT "5 CONFIRMED"; of the 13 real claims, 11 CONFIRMED and 2 OVERREACH, both the orchestrator's own compressions of a lens's narrower sentence. *(Until 2026-09-21 this read "ONE run … 4/4 seeded controls CONFIRMED … one figure that reproduced at no denominator", which fused the two runs and erased the planted negative that makes "it discriminates" a valid inference.)* A combined flow-and-feature audit (2026-09-24): 5 unlabelled controls, **2 of 5 exact, 3 label mismatches, every one in the STRICTER direction, and the run DISCARDED by the pre-registration's own rule** — yet on one control the validator was RIGHT and the orchestrator's TRUE control was wrong (a column the control called granted is in fact denied by its access-control migration; the wrong fact had also reached every wave-2 seat through a panel direction). No false claim was confirmed and no true claim refuted. ⚠️ **So the discard rule punished the validator for an error in the pre-registration**, and this run counts toward the 3 below as *it caught the orchestrator's own fact*, the third branch of the rule — not as ceremony. Folded here 2026-09-24; before that the counter read TWO. A release-model panel (2026-10-05): 16 items, 5 unlabelled controls, **5 of 5 as expected** — 3 true controls CONFIRMED, a planted OVERREACH returned OVERREACH, a planted FALSE CONCLUSION returned REFUTED, though that last control's answer was readable in the record the reader was given, so it shows the reader checks a source and not that it would have found the record unaided; of the 11 real claims, 4 CONFIRMED, 5 OVERREACH and 2 REFUTED, **every one of the seven on the orchestrator's own compression of a seat's narrower sentence, or on a seat's correction it had repeated without checking the definition** (a refusal count "corrected" to exit-1 rows where the ledger's writer defines any non-zero exit as a refusal). One REFUTED was a scope question; re-derived at the vendor's page, it stood. This is run FOUR, the first of the three more asked for in the next sentence, and the third branch of that sentence has now been the yield in every run. **After 3 more runs: if it has caught no overreach and killed no number, it is ceremony — cut it. If its REFUTED verdicts keep needing orchestrator re-derivation, the brief is the problem — give it the architecture. If the orchestrator's own compression is what it keeps catching, that is the finding, and the fix belongs upstream in how findings are written, not here.**
