## Implementation Handoff Step 8 — the gap and its evidence — from `SKILL.md` § Implementation Handoff

   This closes the gap where a defer's dependency dissolves during execution but the todo entry persists with stale reasoning. Evidence (a final audit, 2026-04-16): 3/4 remaining deferrals cited three earlier findings as blockers — all three shipped during the same session. The staleness surfaced only at a later gate; the orchestrator had not re-checked. Cost: ~1 min scan of the 4-field todo entries against the session's commit list. Cost of skipping: defer-discipline credibility erosion + next-session confusion when the todo says "blocked on X" but X is already done.

## Step 2b — why the single-file trigger is load-bearing — from `SKILL.md` § Step 2b: Fix-Wave Diff Review (`--code` on the wave commit — threshold-gated, BEFORE /audit-check)

**The single-file trigger is the load-bearing one:** the old `≥15 files / ≥400 LOC` bars measured wave BREADTH and were blind to DEPTH — a regression-hiding refactor concentrated in ONE file. One audit's wave was 8 files / ~205 src LOC (under both old bars) but carried a **157-LOC refactor** of the highest-traffic critique-wait surface; a single-file change that large warrants a fresh-diff adversarial pass regardless of wave breadth (a 157-LOC port can hide a state-machine / dead-code / contract regression that test-green + fixed-finding verification both miss — the exact Step-2b rationale). The blanket bars were also lowered (15→10 files, 400→250 LOC) since the cost of an extra lean `--code` pass is low vs a shipped regression on a paid surface (cost-asymmetry). Recalibrate UP only if Step-2b fires ≥3× in a row with zero P1s (over-firing).

## Step 2b — why the fixes get a fresh-diff review — from `SKILL.md` § Step 2b: Fix-Wave Diff Review (`--code` on the wave commit — threshold-gated, BEFORE /audit-check)

**Why (codified 2026-06-12; reinforced 2026-06-18 — N=2):** the audit chain reviews PRE-wave code (initial panel), verifies findings-are-fixed + suites-green (final audit / qa), and mechanically gates (/audit-check) — but nobody adversarially reviews the FIXES as a fresh diff. First-instance evidence: a fresh-diff review of the wave commit caught 3 verified serious findings AFTER a 10-expert review + a 12/12 mechanical-gate PASS, all three in wave-NEW code (clamp-helper sibling asymmetry that the same diff's new `.max()` caps had widened; carve-out residual contradictions; ICU `{factor}`-as-subject grammar defect ×12 locales). Grammar, intra-prompt contradiction, and sibling-asymmetry classes are invisible to test suites and to fixed-finding verification — only a fresh-diff design review sees them. **The second instance (N=2) extends the surface:** the reviewed `git diff HEAD` includes the orchestrator's OWN integration-pass inline edits, not just `/agent-work` commits — the fresh-diff review caught a double-pad safe-area regression the ORCHESTRATOR introduced in the integration pass (a base-default on a shared primitive stacking with a per-file completeness-sentinel's per-consumer markers → twMerge can't dedupe across parent/child), invisible to a 15-expert review + 4485 green tests.

## Anti-scope — the deliberately excluded patterns — from `SKILL.md` § Anti-scope

Deliberately NOT in this skill:

- **Full multi-round adversarial debate** (wan-huiyan style) where reviewers see prior outputs and update positions across N rounds. Cost-prohibitive (50-100k tokens per dispute). We use single-pass parallel synthesis + Targeted Verification Step 7a for high-confidence claim-checking. Revisit trigger: ≥2 ALTERNATIVE verdicts on same finding in one audit (restored 2026-07-28 — the 2026-04-18 original was ≥2; it drifted stricter to 3+ here, which made "haven't observed since codification" partly self-confirming).
- **Multi-Run Union Protocol** (wan-huiyan) — running the same panel N times with different random seeds to assess stability. Cadence-prohibitive at our 1-3 audits/session pace. Revisit if re-audit cadence exceeds 3/session.
- **Confirm-by-voting second pass** — N fresh agents fed pass-1's findings to *re-validate / confirm* them. REJECTED 2026-06-14 (7-expert review + 4-lens re-consult). Rationale is STRONGER than cost alone: same-model agents re-checking the same findings are correlated draws (≈2-3 effective from 10), AND feeding findings-as-conclusions anchors the pass into confirming rather than re-deriving — it manufactures phantom consensus Guideline 7 must then discount (negative work). Empirically disproven by a 2026-06-13 experiment (heavy verify fan-out: ~5× cost, 0 net-new; a single orchestrator code-trace beat it). **DISTINCT from what we DID adopt** — Step 7a-ii Lead-Directed Deep Probe feeds the lead as a *coordinate* (verdict STRIPPED) + ground-or-kill + bounded adjacent sweep, capped 3-4 on triaged high-stakes leads, re-deriving from source. The deep-probe is the *anti*-confirm; don't let "add a verification pass" re-surface as confirm-by-voting. (The cost-only rationale on the two bullets above is also upgraded by this: correlated-draw-worthlessness for discovery + anchoring-harm for verification outlast the cost objection as tokens cheapen.)
- **Persona auto-selection from content signals** (wan-huiyan + alirezarezvani). We use evidence-based Panel Playbook (a rolling history of which experts find real bugs per audit class) instead. Revisit trigger: Panel Playbook hit-rate <60%.
- **Phase-fresh synthesis as default** (shinpr) — running the synthesis phase in a fresh sub-agent context. Conditionally trigger-gated for `--phase-fresh-synthesis` opt-in flag. Not default because cross-expert pattern-recognition benefits from orchestrator-accumulated context.
- **`/expert-review` substituting for `/agent-work`.** This skill produces verdicts + recommendations. Code-change execution belongs to `/agent-work` (parallel specialists) OR inline orchestrator edits (≤5 lines per the audit-check Inline-Fix rule). Trivial, clearly-correct fixes MAY be applied inline during ANY audit mode (initial full OR `--final-audit`), provided they're reported back in the synthesis "shipped inline" callout + process log + `/agent-work` already-shipped block; substantive / logic-touching / multi-file changes route to `/agent-work`.
- **`/expert-review` substituting for `/premortem`.** Present-tense panel judgment is orthogonal to future-tense failure-narrative analysis. For irreversible / high-cost / launch-class decisions, run BOTH in series: panel first ("is this the right move?"), premortem second ("if we ship it, what kills it?").
