# Code Review mode — flow/feature/ops scope resolution, sibling distinctions; Code-corpus slice mode — moved, with the copy's edits, from `.claude/skills/expert-review/SKILL.md` (split under the per-file size line, a growth signal and not a delivery limit, 2026-09-26)

## Code Review Step 1b — resolver, LOC confirmation, slice panel, tracker stamp — from `SKILL.md` § Code Review mode (`--code`), Process step 1b (flow / feature / ops scope resolution)

   - **Resolver = union of signals.** For a **flow/feature**: (a) **process-log file-refs** — `rg -o "src/[A-Za-z0-9/_.-]+\.tsx?" plans/flow-<N>-*-process.md` (or `feature-F<N>-*-process.md`) — most authoritative, the audit panel named those files; (b) **tracker-row refs** — `rg -o "src/[A-Za-z0-9/_.-]+\.tsx?"` on the flow's row in `project_critical_flows*.md` / `project_feature_audits*.md` (**the GLOB — the row is in a shard, and the router alone returns nothing**); (c) the audit's **`CODE_PATHS`** list — the SAME map `--v3-drift` Step 1a reads, printed as the "**Code paths:**" line of `python3 scripts/audit-drift-detector.py --target <id>` (not in this copy; one list per COMPLETE audit since 2026-10-06; it replaced the four-entry prose hint table that stood in `references/v3-drift-mode.md`). For an **ops entry (`O<N>`)**: near-DETERMINISTIC — the ops-register row's **`Entry` column IS the anchor code file** (for example, a webhook entry's anchor is its route handler), so surface = that file ∪ its direct imports (the handler modules it calls — `rg "^import.*from ['\"]@/" <entry-file>`) ∪ any `plans/ops-O<N>-*-process.md` refs; tracker = `project_ops_register.md` (ID format `O<N>`, alias `OPS #N`). Union + dedupe → the surface file list.
   - **Print surface LOC + CONFIRM before launching (warn-first, per the warn-before-block discipline).** A flow surface is fuzzy and a whole-surface panel is expensive (a core flow can be 5-8k LOC; one was measured at about 7.7k). Print the resolved files with per-file LOC + total and present for confirmation, so the owner can drop noise (a giant display component) or add a missed file BEFORE the panel fires. A wrong surface wastes a 5-expert panel.
   - **Then run the Code-corpus slice-mode panel** (below) over the confirmed surface — uncle-bob lead + saas-architect + saas-engineer + qa + 1 domain expert (auto-picked from the surface paths per Step 2's path→expert map) — loading the matching `.claude/rules` (Step 3). **Review-unit = design-judgment over WHOLE files** (cross-feature invariant violations, named smells, shared-state pitfalls, dependency-direction), NOT line-by-line (infeasible at flow-surface scale). Partition the surface across experts (no two own the same file). **For an OPS surface** (`src/app/api/**` webhook/cron/route): security-expert + saas-engineer auto-add per the Step-2 path map; a **money-path ops entry** (billing webhook, dunning/refund/reconcile cron) ALSO weights haines-churn-prevention + ops-monitor (dunning and failed-payment recovery, and the job's run health; the blast-radius override, within the 5-cap).
   - **Tracker stamp:** stamps the row's `c:YYYY-MM-DD` audit-tier token — `c:` is BROADENED to "a `--code` review ran" (fix-wave diff OR whole-surface; the narrative cell records which). Does NOT flip Status or run `/audit-check` — Curate-layer advisory, like every `--code`. (Ops-register rows use the `prov`/`c` token grammar, so an OPS `--code` stamps `c:` there.)

## Code Review — the record a `--code` panel on a commit leaves (the migration review gate's input)

After a `--code` panel on a commit (every diff form but the bare one, one record per reviewed commit; the bare form reviews the uncommitted tree and has no commit to record), write the synthesis verdict to `.claude/reviews/<full-commit-sha>.md` — one file per reviewed commit, the FULL 40-hex sha in the name — and commit it. **The first non-blank line is the verdict word, first and unqualified:** `APPROVED`, `APPROVE` or `FOLD-VERIFIED` approves; anything that qualifies it in the same leading window (`APPROVED WITH FINDINGS`, `APPROVED — 2 P2 open`, `APPROVED FOR <sha> ONLY`, another verdict beside it) does not, and so does any other opening (`CHANGES-REQUESTED …`, `HOLD …`, `IN REVIEW …`). On the next line, `Reviewed-by:` and the seats that sat (the panel's lenses; a review session adds its own id); then the findings (severity, `file:line`, disposition). The migration runner (`scripts/run-migration.mjs`, through `scripts/lib/migration-review-gate.mjs`) reads this file AS COMMITTED at HEAD — never the working tree — for the commit that last changed a `supabase/migrations/*.sql` file, and refuses the apply without an approving one. A record with no `Reviewed-by:` line, or one naming nothing but the reviewed commit's own session (its `Claude-Session:` trailer), is not an approving one. The panel's fresh helper agents are the reviewers, so a panel run in the session that wrote the commit qualifies. So: open with the approving word only when nothing is owed, keep narration past the first line, and commit the record before the apply. A fold that changes the migration file moves the commit that needs a record: review the fold and write its own. A non-approving record is still worth committing — it is the review's trail, and the next panel on that commit reads it.

## Code Review — distinct from siblings, anti-scope, revisit — from `SKILL.md` § Code Review mode (`--code`), the closing block after its Process steps

**Distinct from siblings (so it doesn't overlap):**
- **vs `--lean`:** lean takes a TOPIC you write; `--code` reads the DIFF and derives the topic + experts + matching rules itself.
- **vs Code-corpus slice mode (below):** slice is SURFACE-scoped (you name `src/lib/billing/*`) with a fixed 4-5 panel for cross-cutting infrastructure audits; the DIFF forms of `--code` are diff/PR-scoped with an adaptive, uncapped panel for fresh changes. **`--code <flow|feature|ops>` IS slice-mode's auto-resolved front-door** — it resolves the surface from a tracker ID instead of you naming paths, then runs the same slice panel (use it for a TRACKED flow/feature; use bare slice-mode for an ad-hoc infra surface that has no tracker row).
- **vs the diff forms (`--last N` / `--session` / bare):** those review CHANGED lines; `--code <flow|feature|ops>` reviews the WHOLE resolved surface (design-judgment over all of it), for an already-shipped flow with no pending diff.
- **vs `--final-audit`:** final-audit verifies previously-implemented fixes against a finding checklist (post-implementation gate, tracker-bound, flips COMPLETE + runs `/audit-check`); `--code` (any form) reviews code without a checklist + never flips Status — Curate-layer advisory, not a gate.
- **vs native `/code-review`:** native follows `CLAUDE.md` (its vendor page, read 2026-10-21) and is generic-bug-focused; `--code` loads the path-scoped `.claude/rules/` the changed paths match and uses domain experts with MEMORY. Use native `/code-review ultra` when you want raw multi-agent breadth; use `--code` when you want THIS project's conventions enforced.

**Anti-scope:** not a launch gate (that's `--final-audit` + `/audit-check`); not for ad-hoc whole-surface infra audits you name by path (that's bare slice mode — though `--code <flow|feature|ops>` IS the tracker-ID front-door to it); not a substitute for the pre-push hook / sentinel tests (those are the Enforce layer — `--code` is a Curate-layer human-in-the-loop review, complementary).

**Revisit:** if `--code` fires 5+ times and the auto-selection consistently mis-picks (owner overrides the panel), the path→expert mapping needs tuning — fold corrections into the Routing Rules table. If owner consistently runs native `/code-review` instead, this mode isn't earning its spec surface — prune. **Flow/feature-scope resolver (Step 1b):** if the owner edits the confirmed file list ≥2× for the SAME flow, that flow's `CODE_PATHS` list needs the corrected files — add them (the resolver is heuristic by design; the confirmation-gate + the `CODE_PATHS` list are how it converges). If 3 flow/feature `--code` runs land zero findings the per-feature audit chain wouldn't have caught, the whole-surface mode duplicates slice-mode/`--final-audit` — reconsider.

## Code-corpus slice mode — invocation, companion script, anti-scope, promotion trigger — from `SKILL.md` § Code-corpus slice mode, the section's whole body

Use when auditing a cross-cutting surface that isn't on the flow/feature/ops tracker — typically shared infrastructure (`src/lib/email/*`, `src/lib/ai/*`, `src/services/*`, `src/db/schema.ts`, `src/lib/billing/*`). Codified 2026-05-27 from a review's finding: "corpus-wide design judgment, only fillable by a skill".

**Invocation:** topic `"audit code-corpus slice <surface>"`. Orchestrator scopes the slice + composes a 4-5 expert panel: **uncle-bob lead** + saas-architect + saas-engineer + qa-expert + 1 domain expert (e.g., security-expert for `src/lib/billing/*`, prompt-engineer for `src/lib/ai/*`). Briefing template: "audit this slice for cross-feature invariant violations, duplicate helpers, shared-state pitfalls, and Clean Architecture dependency-direction violations."

**Companion script:** `scripts/code-hotspot-scan.sh` emits hotspot JSON (LOC × churn matrix, coupling, server-action-without-test, schema drift, npm-outdated). Run this BEFORE the panel and inject the output into each expert's brief to scope the audit to actual hotspots within the slice.

**Do NOT auto-write findings to `todo.txt`.** Findings live in synthesis output only; promotion requires explicit owner decision per finding (same protocol as standard /expert-review, per its deferrals rule).

**Anti-scope:** this preset is NOT a substitute for per-feature audits — `/flows`, `/features`, `/ops` trackers remain the right shape for business-surface audits. Slice mode covers cross-feature shared-infrastructure only.

**Promotion trigger to first-class `/code-audit` skill:** if this preset fires 3+ times AND produces findings the per-feature audit chain wouldn't have caught, promote to standalone `/code-audit` skill. Until then, preset is the right shape (sentinel-shaped gaps go to CI tests; design-judgment-shaped gaps go to this preset).
