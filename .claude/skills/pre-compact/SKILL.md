# /pre-compact — leave the seat in a state a compaction cannot lose

The command codifies a preparation first done by hand: disarming the mail listener is a parameter, `--disarm`, and without it the listener stays on; either way the recovery after the compaction re-arms it. The founding instance ran by hand on a paused seat: the listener stopped and confirmed dead, a dated block written into the working plan naming the pause, the banked reader, the hub's dispositioned verdict and the files to reopen, the plan synced, one line back saying ready.

## Why a command, and why these acts

`/post-compact` rebuilds a seat's state after the compaction from the transcript index and the working plan. It is only as good as what the plan carried when the summary was cut, and two things reliably go wrong at that moment:

- **The listener (`--disarm` only).** By default the listener stays on: the seat is still awake and the standing directive wants it listening. With `--disarm` it is taken down first, for a seat that should not spend turns on inbound mail until the compaction has landed (the founding case: a paused seat). Either way the listener is ON again after the compaction: `/post-compact` step 5 re-arms a dead one on the first turn after the summary (its exceptions: a standby marker, and a setup that switched the listener off with `SKIP_MAIL_LISTEN_ARM_REMINDER=1`). What `--disarm` buys is a KNOWN state — a compaction can kill a listener silently or a resume can leave two, both measured in the orchestrator doctrine — and no mail landing in a context about to be summarised.
- **The hand-off state.** The summary is an index, not evidence. A builder still running, a hand-back banked but unverified, an uncommitted edit in the shared tree, a verdict read but not folded, a question put to the owner and not answered — each survives only if the plan names it, with a content key the recovery can re-check rather than a status word.

## Process — `/pre-compact [--disarm] [--fleet] [--pause]` (`--fleet`: each other open seat that takes a turn within 10 minutes; § Boundaries and `pause/SKILL.md` § Fleet)

**`--pause` (both routes exist, and `--disarm` means the same on each):** this command then runs `/pause --compact` through the Skill tool, with `--disarm` when given, and does nothing else itself (but a `--fleet`'s wake mail, § Boundaries): `/pause` enters the pause and runs this command again without `--pause` (`pause/SKILL.md` § Fleet and compact forms), so the work holds and the seat is banked in one turn. `--resume` and `--cold` are `/pause --compact`'s: typed here they are not passed on, and the readout says so. Typed with `--fleet`, the other seats get it as `/pre-compact --disarm --pause` and take the same route. Without `--pause`, steps 0-4 run as written and this command holds nothing.

0. **Preconditions, stated.** `ListAgents` plus this session's rows in `.claude/logs/subagent-dispatch.jsonl` give the in-flight builders (the log, not recall). Read the markers: `session-pause-<sid8>` (a pause keeps holding; this command changes nothing about it), `session-standby-<sid8>` (it cannot still be standing: this command is the owner's message, so `standby-resume-check.sh` has already directed `/standby resume` — marker cleared, listener re-armed — and the seat is awake by step 1; to keep it parked through the compaction, the owner runs `/standby` after this and BEFORE `/compact` — the order is `/pre-compact`, `/standby`, `/compact`; a `/standby` sent after the compaction lands on a freshly compacted seat, whose turn runs the recovery first and re-arms the listener only for `/standby` to stop it again, so a readout never tells the owner "`/compact`, then `/standby`"), `review-hub-active-<sid8>` (a hub says so in its readout; peers keep mailing it). Nothing is stopped except the listener (and a hub's staleness poller and usage watch, under `--disarm`): builders finish and hand back on their own, background shells keep running.
1. **The listener (and on a hub, the staleness poller and any usage watch).** Without `--disarm`: leave it armed and say so (a dead one is re-armed as usual, now). With `--disarm`: `TaskStop` the mail-listen Monitor task; then `kill -0 "$(cat .claude/state/mail-listen-<sid8>.pid)"` must FAIL — a stale pid file reads live under `[ -f ]`, so the verdict is the kill test, not the file. Say it is dead, and say when it comes back: the recovery after the compaction re-arms it. On a review hub (`review-hub-active-<sid8>`), write the hub's own arm command into the block — `mail-listen --poll 30 --rebroadcast-hours 48` (`review-hub/SKILL.md` Phase 1) — because every post-compaction arm directive prints the bare one. **A hub has a second Monitor, the staleness poller (`review-hub/SKILL.md` Phase 1), and `--disarm` stops it too**, and the recovery after a compaction turns it back on, the same way it does the listener: bank its arm command first (below), then `TaskStop` it, then `pgrep -P $PPID -f '[h]ub-stale-request-poll'` must print nothing (`-P $PPID` keeps a peer hub's poller on the same box out of the answer; never `pkill` by pattern, which would kill the peer's alarm too). An earlier version of this step left the poller running, since no recovery step brought a stopped one back; that step now exists. Without `--disarm` the poller stays armed. **A hub that armed a usage watch (`review-hub/SKILL.md` § ⏸ step 6, whose plan line reads `usage watch armed: --pause-at N`, or a resume watch of steps 7-7b) has a THIRD Monitor, and `--disarm` stops it too** (an earlier version of this step left it running, and a watch that fires wakes the seat): say in the block that it was stopped (step 2), then `TaskStop` it, then `pgrep -P $PPID -f '[h]ub-usage-watch'` must print nothing. Its command is not banked: `/post-compact` step 5 re-arms a dead watch by § ⏸ step 9, which rebuilds it from the pause marker or the plan line, so with no pause marker and no `usage watch armed:` line in the plan, write that line (step 6's) before stopping it, or nothing brings it back. Without `--disarm` the usage watch stays armed, and it too dies on its own at the Monitor's 30-minute cap; the same step 5 line re-arms it. **On a hub, with or without `--disarm`, write the poller's arm command into the block, with `timeout_ms: 1800000` beside it** — the NEWEST poller arm in this session's own transcript, which survives a compaction (a context, or a bank, may not): `python3 -I -c 'import json,sys;c=[b["input"]["command"] for l in open(sys.argv[1]) for b in ((json.loads(l).get("message") or {}).get("content") or []) if isinstance(b,dict) and b.get("name")=="Monitor" and "hub-stale-request-poll" in b.get("input",{}).get("command","")];print(c[-1] if c else "NO-ARM")' ~/.claude/projects/<project-key>/$CLAUDE_CODE_SESSION_ID.jsonl`, its `grep -v` filter lines included; never reconstruct it from `ps`, which returns the harness's shell wrapper (a snapshot `source` and an `eval '…'` with every quote re-escaped), not the command. `NO-ARM` ⇒ bank Phase 1's loop and say its filters are lost. ⛔ **Bank, and re-arm, the loop TEXT itself — never a `bash <file>` that holds it**: the `pgrep` check above, `/post-compact` step 5's liveness check and this extractor all key on the string `hub-stale-request-poll` in the Monitor's own command, which a file-form arm does not carry (the usage watch's check keys on `hub-usage-watch` the same way). Measured 2026-10-23 on a hub re-armed after a compaction as `bash <scratch>/poller-cmd17.txt`: the check printed nothing (read as stopped) while that alarm was running and fired seconds later, so a recovery would have armed a second copy (double alerts), and the extractor would have banked an older arm. Inline, the same check printed its pid. Why: `/post-compact` step 5 re-arms a dead poller from the bank and otherwise falls back to Phase 1's bare loop, which re-fires every row the hub had filtered out; and a poller dies on its own at the Monitor's 30-minute cap, so an automatic compaction without `--disarm` can find it dead too. The standing arm-the-listener directive re-injects every turn until then; the owner's flag overrides it for those turns.
2. **Bank the state — one dated `PRE-COMPACT` block in the working plan, outside the `SUMMARY-SYNC` fence** (`grep -n -F 'SUMMARY-SYNC' <plan>` prints both fence lines; write below the second). ⛔ **Head it exactly `## PRE-COMPACT — <date -u +%FT%TZ>`** (then ` (AUTO)` when the hook directed it, or the owner's flags): `/post-compact` finds the bank by that heading and its UTC time, and a heading with no time cannot be placed, so the recovery falls back to the full rebuild. Every timestamp DERIVED (`date -u`, a mail file's `created:`, `git log --format=%ct`), never typed. The block carries:
   - the owner's words, verbatim; HEAD; this seat's commits since its last readout;
   - each in-flight builder — name, what it builds, the files it holds, running or handed back and banked (agent ids stay in a session-private scratch file, never in the plan);
   - every uncommitted edit of this seat — `git diff --numstat` on its paths and ONE content key per unit (`grep -cF '<a line only that edit holds>' <file>`), so the recovery can tell "still in the tree" from "swept into a peer's commit" from "lost";
   - the open mail loops: requests sent and the verdict owed, verdicts read and their dispositions, holds standing;
   - what the owner has been asked and has not answered;
   - the NEXT STEP as a numbered order (or a pointer to the pause block's resume order when one exists), and whether the listener (and on a hub, the poller and any usage watch) was disarmed (so the recovery knows to re-arm it);
   - the scratch files and patches to reopen, by path;
   - on a hub, the poller's arm command with `timeout_ms: 1800000` beside it (step 1).
3. **Sync and check the plan.** `node scripts/summary-plan-sync.mjs`; `git ls-files --error-unmatch <plan>` (untracked ⇒ say the plan is unprotected); the heading diff against HEAD (`diff <(git show HEAD:<plan> | grep '^#\+ ') <(grep '^#\+ ' <plan>)`) — `<` lines are destruction, stop and restore.
4. **Readout, one short block, in the owner's register:** the listener's state (armed, or disarmed and re-armed by the recovery), and on a hub the poller's and any usage watch's too; what the plan now carries (builders, uncommitted work, loops, next step); what the recovery will do after the compaction (`/post-compact` on the first turn; a pause keeps holding); that the owner's next move is `/compact` — or, when the owner wants the seat parked through it, `/standby` and then `/compact` (step 0) — and, when the work after it needs a model switch (`/model opus`, plus `/effort high` before a `/wrap`; or `/model fable` back), that the switch comes after the compaction, never before. Say that keep-warm stops at the `/compact` — by design, whether or not `--disarm` was passed (a compaction is how the owner switches accounts, waits out a limit or switches models: `pause/SKILL.md` step 6b) — and never quote a "warm until" time past the `/compact`. Say the session then waits for the owner's next message only with `--disarm`: without it the listener stays armed, so a peer's mail can wake the seat and run the recovery first (the reason for `--disarm`: so listeners do not wake the session). No plan table. **When the hook directed it (AUTO):** one line instead — the bank is written, the automatic compaction will land on its own, `/post-compact` will start from this block — then carry on with the work the hook interrupted; there is no `/compact` to ask the owner for.

## Automatic trigger

The rule: run `/pre-compact` automatically when the context nears the automatic compaction (about 96% of it), and optimise for the save running close to that point, not for how large a command fits in the window left; a save the compaction cuts off is acceptable. `/post-compact` checks whether a save ran: if it did, the recovery starts from the bank and has less to do; if not, it rebuilds as before.

- **The hook:** `.claude/hooks/auto-precompact-trigger.py` (PostToolUse on every tool, and UserPromptSubmit). When the tokens left before the compaction point fall to 30,000 or fewer, it puts one `⏳ AUTO PRE-COMPACT` line in the seat's context, once per crossing; the seat runs this command through the Skill tool, without `--disarm`, before anything else in that turn. The size is the newest main-chain reply's usage in the transcript; the compaction point is `compact_threshold` from the status-line file.
- **Why 30,000:** the save's own cost, measured 2026-10-13 over the 46 `/pre-compact` runs in this project's transcripts (command to the end of its turn): min 3,509, median 8,422, max 23,629 tokens. 30,000 is about 96% of a 727,000 compaction point; it does not always cover the save, because the reading moves one model call at a time and lags by the tool results since then: replayed over this project's transcripts, a median-cost save misses on ~10% of crossings, the largest on ~41% (40,000 -> ~6%, 50,000 -> ~3.5%). The design runs close to the compaction. A save the compaction still cuts off costs its own tokens and nothing else: `/post-compact` finds no fresh bank and rebuilds in full. `AUTO_PRECOMPACT_HEADROOM` in the settings env block moves it.
- **Switched on per session:** `.claude/state/auto-precompact-pilot-<sid8>` (one session) or `.claude/state/auto-precompact-enabled` (every session, with the headroom at 30,000; the marker is gitignored local state, so it reaches this checkout only); `auto-precompact-off-<sid8>` opts one session out. Off for everyone: delete the marker and any `auto-precompact-pilot-<sid8>` marker (read on every call), or `SKIP_AUTO_PRECOMPACT=1` in the settings env block (read at each session's next launch). Never for a sub-agent, a `[keep-warm]` ping, or a seat parked by `/standby`. Fires: `.claude/logs/auto-precompact-fires.jsonl`.

## Boundaries

- **Owner-invoked, directed by the AUTO PRE-COMPACT hook, or directed by a FLEET directive — nothing else.** A fleet directive is the hook's `⏳ FLEET PRE-COMPACT` line: the owner typed `/pre-compact --fleet [--disarm] [--pause]` in another session (the owner's own typed record, checked by `.claude/hooks/fleet_verb.py`; § Fleet in `pause/SKILL.md` has the whole mechanism), and this seat runs `/pre-compact` with the same flags minus `--fleet`, as if the owner had typed it here (no `(AUTO)` on the heading). Typed here WITH `--fleet`: run the save here, then send the one wake mail that § describes. Hook-directed (AUTO) means the hook's `⏳ AUTO PRE-COMPACT` line is in this context and `.claude/state/auto-precompact-fired-<sid8>` exists; a seat's own reading of its context size is never the hook, and `(AUTO)` goes on the heading only then. A seat never decides on its own to prepare a compaction; an automatic compaction the hook did not catch gets the recovery, not this.
- **Writes the working plan and nothing else.** No commit (a paused seat does not commit, and outside a pause a commit is the work's own step, not a compaction's), no mail except the one wake mail of a `--fleet` typed here (`pause/SKILL.md` § Fleet), no tracker or memory write, no `/meta learn`. A session that holds unpersisted decisions says so in the readout; `/wrap --checkpoint` is the owner's call.
- **A `/compact` typed before the bank lands is refused ONCE**: `compact-save.sh` runs `.claude/hooks/precompact-save-guard.py` first, which blocks a MANUAL compaction when this session's newest `/pre-compact` request (typed by the owner, or run for the owner by a FLEET or AUTO hook line) is under 10 minutes old and no `## PRE-COMPACT` heading in its plans is at or after it; the refusal writes no checkpoint and no post-compact-pending marker (only the guard's own once-marker and its fires line), and any manual `/compact` in the 10 minutes after a refusal goes through (at most one refusal per 10 minutes). An automatic compaction is never refused. Founding race: a `/compact` 6 s after `/pre-compact`, no bank. Not yet seen firing on a real compaction (the tests drive the real hook in a throwaway folder); fires: `.claude/logs/precompact-save-guard-fires.jsonl`.
- **Not `/pause`:** it holds nothing and running builders keep running, unless `--pause` was given, which routes through `/pause --compact` (§ Process). **Not `/standby`:** the seat stays awake and answers the owner.
- **The listener's return is `/post-compact`'s step:** it re-arms a dead listener on the first turn after the compaction unless a standby marker exists (a parked seat stays deaf) or the listener is switched off (`SKIP_MAIL_LISTEN_ARM_REMINDER=1`). When the owner's `/compact <focus>` lets the recovery be skipped, `session-start.sh`'s arm directive (source-agnostic: dead pid, no standby marker, the switch unset) and `mail-listen-arm-reminder.sh` still bring it back on that turn. A paused seat gets it back then too — `/pause` keeps the listener on while paused. **A hub's poller has no such second path:** after `--disarm`, a skipped recovery leaves it dead until the hub re-arms it by hand (`review-hub/SKILL.md` Phase 1, or the bank's line), so the readout says a `/compact <focus>` would leave it down.
