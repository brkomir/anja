# Deep-pass — the parallel-agent transcript scan

Moved out of `.claude/skills/wrap/SKILL.md` because the procedure earned its own
command. In the source project nothing was cut, reworded or summarised in the move; the text below
is that text as the source project later amended it, with the copy's edits, and `/wrap` now carries the trigger plus a
pointer here.

**Why it moved, measured rather than asserted:** it and the rest of the wrap spec co-changed in 6% of
commits; it fires on roughly half of wraps (13 of 54 session plans carry its plan line, 39 of 54
mention it); it has a consumer outside `/wrap` — `post-compact/SKILL.md` Step 5 re-opens it at the
post-compaction moment; and it was 26.5% of the spec's bytes while taking 36% of all growth since the
2026-08-28 extraction. Precedent: an earlier change moved the recovery procedure out of `meta/SKILL.md` the
same way, keeping the alias so nine callers needed zero edits.

⚠️ **Its ledger did NOT move.** The sampled-measurement registry stays where it
is: 14 files cite it by path, several of them immutable archives, and it is
already outside the injected payload — so moving it would break every citation to buy nothing.

1b-DEEP. **Mandatory PARALLEL-agent deep-pass for HUGE / multiday sessions.** The inline Step 1b scan (`.claude/skills/wrap/SKILL.md` § Process, step 1b, the compaction-boundary scan) is orchestrator-run → it systematically UNDER-scans a huge multiday session (author-blindness + the harness summary compresses pre-compaction arcs to bullets). RECURRING pattern: twice a wrap was found materially incomplete (a later check found 8 gaps), then a multiday session's wrap was found to lack substance — the inline wrap had codified only 1 lesson for a 56-commit session. And a SINGLE fresh-context deep-pass agent STALLS on a large transcript (2026-07-01: 7.4 MB / 2460 lines → 600s watchdog, no recovery). Fix = a BOUNDED PARALLEL deep-pass, AUTO-fired (not owner-prompted).

   **Trigger — auto-detect (fire when this session compacted — a record, per /wrap Step 1b's Detection, auto or `/compact` — AND either bound is crossed):**
   ```bash

   # STRIP FIRST, then measure — see the byte-unit rule below. TXT is the scan target for EVERYTHING downstream.
   # (filename deliberately avoids the `wrap-dp-<wordchar>` shape — that string in THIS spec would
   #  false-positive wrap-reconcile.mjs's deepPassRan transcript-grep, same trap as the digit rule below)
   TXT=/tmp/wrap-stripped-${CLAUDE_CODE_SESSION_ID}.jsonl   # SESSION-SCOPED — see below
   # ⛔ BLANK THE IMAGE PAYLOAD, NEVER DELETE THE LINE. A `grep -v` on the base64 marker stood here until 2026-09-15
   # and deleted every owner message sent WITH A SCREENSHOT, its text and rulings included (measured on one
   # session: 9 typed owner records in the raw transcript, 8 in the stripped copy; the lost one carried two rulings),
   # and it shifted every later line number off the raw transcript. The payload sits under TWO keys per record,
   # `source.data` and `toolUseResult.file.base64`, so the pattern names both: a `data`-only form kept 397,933,828 B
   # across 250 transcripts and one line of 3,102,592 B, more than a whole agent slice.
   # Keep the replacement a NON-raw string; a raw one writes literal backslashes into the JSON. Same pattern:
   # blankBase64Payloads in scripts/wrap-reconcile.mjs and transcript_bytes in scripts/wrap-preflight.py; after any edit to the base64
   # half here, run the three on one transcript and compare their byte counts (the two siblings blank base64 only; the request-copy
   # stub below is this block's alone, so a transcript with request copies reads smaller here than there).
   # ⛔ AND BLANK THE HARNESS'S REQUEST COPIES TO A ONE-LINE STUB, NEVER DELETE THEM.
   # Since harness 2.1.300 (first seen 2026-10-14T21:36Z) the harness writes `api-request`, `api-request-blob` and `api-request-shape` records, a copy of each request
   # sent to the model; measured 52-65% of every transcript's bytes from their first appearance (5 sessions), so a slice
   # agent spent half its reading on duplicate conversation. A stub keeps every line
   # number, for the reason above; every such record starts `{"type":"api-request`, so the test is a prefix, never a substring.
   python3 -c 'import re,sys
R=re.compile(r"^\{\"type\":\"(api-request[a-z-]*)\"")
for l in open(sys.argv[1],encoding="utf-8",errors="replace"):
    m=R.match(l)
    sys.stdout.write("{\"type\":\"%s\",\"stripped\":\"request copy\"}\n" % m.group(1) if m else re.sub(r"\"(data|base64)\":\"[^\"]{200,}\"","\"\\1\":\"<stripped>\"",l) if "\"type\":\"base64\"" in l else l)' "$TX" > "$TXT"
   BYTES=$(wc -c < "$TXT" | tr -d ' ')
   COMMITS=$(git log --oneline <session-start-sha>..HEAD | wc -l)   # session span; peer over-count is safe (it only raises the fire-rate)
   # FIRE the parallel deep-pass if Step 1b counted a compaction record AND (BYTES > 3000000 OR COMMITS > 20)
   ```
   Below both bounds (or no compaction record) → the inline 1b scan is sufficient; skip.
