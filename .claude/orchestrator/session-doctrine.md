## RE-RESOLVE A SHARD FILENAME AT WRITE TIME — `cat >>` to a rolled name creates a dead orphan, exit 0

A shard name encodes its END DATE, so `cat >> <old name>` writes an orphan the moment a peer's roll renames it. **TELL: `create mode 100644` on what you believed was an APPEND, and `git diff --numstat -- <declared paths>` printing one row FEWER than declared.** ⛔ **AND THE RADIUS IS EVERY SHARD IN THE DIR, NOT THE ONE YOU ARE APPENDING TO — WHICH IS THE HALF EVERY READER SCOPES AWAY, BECAUSE APPENDING IS THE ACT THIS RULE WARNS ABOUT.** `splitMemorySharded` is a greedy SINGLE-PASS re-pack over the WHOLE corpus in document order against a byte budget, holding no memory of prior boundaries, so any upstream byte change re-flows every boundary downstream. Measured (2026-09-06): **8 renames, 7 of them HISTORICAL**, the oldest an APRIL shard, renamed that night. **So ANY shard path — a commit message, a register line, a tracker row, a rule citation — is a dead path after ANY roll, and the reader meets it as a clean empty grep over live content. Verify a filing by CONTENT across the dir, never by the path it was written under.** ⛔ **RESOLVE BY MAX END-DATE — this line prescribed `ls -t … | head -1` until 2026-08-27, and that is MTIME order, a different question.** Measured that day: `ls -t` returned a `…-2026-07-26.md` shard where the current one ran to `2026-08-27`, so the codified recipe selected the stale shard this rule exists to prevent. Parse the trailing date out of the name and take the max — ⚠️ **anchoring the glob to `MEMORY-ARCHIVE-20*.md`, which is load-bearing rather than tidy: undated siblings exist (`MEMORY-ARCHIVE-legacy-lessons-L*.md`) and the obvious `sort | tail -1` puts `legacy` AFTER `2026` and returns one** (a reviewer demonstrated that on themselves while checking this very rule). Guard the result non-empty — or just use the WORKING resolver at `.claude/skills/meta/references/process-learn.md` (grep `Current shard by MAX END-DATE`), which survives hyphen-rich absolute paths, undated `legacy` siblings and month-boundary sets. Do NOT hand-roll it: `awk -F'-' '{print $NF}'` over a full PATH returns the DAY, so `31` beat `30` and picked a rolled-off shard — this section's history is two wrong recipes. ⛔ **`--heal` MUTATES, AND IT HAS TWO CLEAN VERDICTS — READ WHICH ONE YOU GOT.** `CLEAN — N repaired` is the mutating path; `CLEAN — scanned=N, all current, nothing written` is emitted inside `if (!fixable.length)` and EXITS BEFORE the repair loop, so it structurally cannot accompany a write. ⚠️ **This line claimed the no-write verdict prints DURING a rename until 2026-09-01, and that was FALSE and inverted the remedy** — it told readers to distrust the one reliable discriminator, and on a shared tree that invites blaming a peer's dirt on your own command. Two runs, not one lying run. Size IS blind (same bytes, different hash): `git status --porcelain -- <dir>` after every heal. Archive.

## COUNT UNREAD MAIL WITH `session-manifest.py mail-check --peek` — `grep -v '\.read$'` COUNTS RECEIPTS AS UNREAD

⛔ **FIRST: THE FILENAME IS `<recipient>__<ts>__<sender>.md`, SO `*__<me>.md` IS MAIL *I SENT*, NOT MAIL SENT TO ME — AND THE INVERSION RETURNS A CONFIDENT WRONG NUMBER WITH A PASSING CONTROL.** Measured 2026-08-26: a session globbed `*__<peer>.md` believing it was its own outbound, got **1/1** against a control, and concluded a peer was mistaken about a missing verdict; re-derived against the correct glob it read **0** and the peer was right. **The control inverted with it**, because both arms were drawn from the same wrong population. Mail TO me is `<me>__*`; mail FROM me is `*__<me>.md`. ⛔ **AND THAT SENTENCE IS ITSELF THE TRAP: A MAIL THE RECIPIENT HAS READ IS `*.md.read`, SO A GLOB COPIED FROM IT SILENTLY EXCLUDES EVERY VERDICT THAT LANDED.** Measured 2026-08-27: four probes in one sitting all globbed `*__<me>.md`, all missed a verdict sent 12 min after its request, and their AGREEMENT read as corroboration — four copies of one mistake. The commit was re-reviewed, then the peer was told it had sat 3 h, then that was retracted with a replacement explanation ALSO false. **The better the peer is at reading your mail, the more certainly your own sent-mail glob loses it. Use `.md*` when you are ENUMERATING the store; keep the `grep -vE '\.read(-by-[0-9a-f]+)?$'` form below when you are COUNTING UNREAD — they answer different questions and sit two paragraphs apart with nothing saying which is which. And never count agreement among probes you wrote in one sitting as corroboration.** ⛔ **`review-request-closure-scan.mjs` filters `.md` OR `.md.read`, which is broader than any hand-glob and still NOT the whole store: a broadcast receipt is `.md.read-by-<sid>`, and one such file today has NO `.md` base, so it is invisible to that scanner by construction** (measured 2026-08-28: 651 `.md` · 24 `.md.read` · 4 `.md.read-by-*`, one orphaned). It was the best instrument in the room and the one I accused; it is not an exhaustive one. ⚠️ The convention IS documented — `mail/SKILL.md` — but that spec loads on `/mail`, and the specs that MANDATE enumerating the store (review-hub's queue derivation, `/wrap` Step 0, the post-compact store sweep) do not load it; `session-manifest.py`, which CREATES the files, states it nowhere. **An instruction and its precondition living in specs that never co-occur is why this is here, in the file everyone already has.**

Broadcast mail (`all__<ts>__<sender>.md`) accrues one `.read-by-<sid>` receipt PER READING SESSION, and `.read-by-<sid>` does not end in `.read`, so the negation keeps every receipt — over-counting in proportion to fleet size × broadcast volume, i.e. exactly when you are triaging. **If you must glob, exclude both suffixes (`grep -vE '\.read(-by-[0-9a-f]+)?$'`) and state the recipient scope you filtered on.**

## NAME THE INSTRUMENT BEFORE YOU PUT A SEAT'S NAME NEXT TO A SHA — the tempting proxy is the commit's VOICE

One seat's commit routinely SWEEPS another's uncommitted lines, so a commit's content says whose work it CONTAINS, never who RAN it. **DOES NOT answer it:** `git log --author`/`%an` (one identity fleet-wide) · `-S`/`git show` (name the commit, not the seat) · the body's voice · mtime. **DOES, ranked, all one-directional:** (1) the `Claude-Session:` trailer (PARTITIONS by runner, never identifies an author; its ABSENCE proves nothing — archive) — ⛔ **and its VALUE has THREE shapes, so an exact 8-hex compare reads a compliant seat as having done nothing: 8-hex, a hosted session URL, and a full UUID. A PREFIX MATCH CATCHES TWO OF THE THREE, NEVER THE URL.** ⚠️ The URL form DOES partition, and it also JOINS to a seat: `scripts/session-labels.py` maps it through each session's own `remote_session_change` records (a membership test per seat: to name an unknown URL's seat, run `urls --sid` over every transcript) — attribute with that reader, never an 8-hex-only match, which reads a URL-form seat as idle; ⛔ **but only for commits from 2026-09-02 on: the harness wrote no `remote_session_change` record before 2026-09-01, so an earlier URL joins to NO seat and reads idle there too — attribute those by (3)**. **No percentage belongs here — the ACTION is the same at any rate, which is `bash-environment.md`'s own trim test.** Measured spread + windows: archive; (2) `Co-Authored-By` — a MODEL partition that can EXCLUDE, not identify — ⛔ **and it stamps the model you CONFIGURED, not the one that SERVED: two commits carry `Claude Fable 5` from inside a measured 307-turn `claude-opus-4-8` window (2026-09-02), so it cannot reliably EXCLUDE either; only `.message.model` dates a model**; (3) the committer's own transcript creation record — readable from ANY seat: a fixed-string search (`rg -l -F`) for a SHORT fragment with no quotes or backslashes (JSON escapes both) over EVERY transcript — top-level `*.jsonl` AND `*/subagents/*.jsonl`, with NO mtime filter (a shared file's mtime post-dates its writer's transcript) — then the EARLIEST assistant `tool_use` carrying it: an `attachment` or `bashEditDiff` hit is a READER, a later `tool_use` a RE-WRITER (said *visible only to that seat* until 2026-09-23).
