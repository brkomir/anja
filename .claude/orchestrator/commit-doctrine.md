**HAND-STAGED HUNK ISOLATION (`hash-object -w` + `update-index --cacheinfo`) — five things it arms.** ⭐ **`node scripts/stage-own-hunks.mjs <path> --key <your text> --exclude <their text>` does this for you**: blob built from HEAD plus only your hunks, mode read from HEAD's tree (closes 1 below), the blob's line count checked against the kept hunks before it stages. **Pass `--expect +N/-M` with your own edit's counts whenever you can count it:** it refuses when the kept hunks' totals differ, which catches another session's line inside a kept hunk (an adjacent added line, a DELETED line next to or near yours, wherever the lines between repeat, blank lines included) and one of your deletions landing in their hunk. Either way read the `left out:` lines it prints — each shows its changed lines, and every one should be another session's. `--exclude <their phrase>` catches only a line holding that phrase. `--strict` refuses a kept added line carrying none of your keys, and a kept hunk removing more lines than it adds unless every removed line carries one of your keys (`--key-in-removed`); it cannot see another session's deletion in a kept hunk that adds at least as many lines as it removes (+1 -1, +2 -1). ## GATE A SCRIPTED EDIT ON BOTH NUMSTAT COLUMNS, COUNTED FROM YOUR OWN EDITS, IN THE SAME COMMAND AS THE COMMIT

`git diff --numstat` emits **ADDED, DELETED, PATH**: a DELETED discrepancy means you destroyed a peer's line (loses WORK), an ADDED one means you are committing their work under your message (loses PROVENANCE). **Count your own edits into `--add` / `--del` — ⛔ NEVER pipe the pair out of `git diff --numstat`** (the gate then compares the diff to itself and cannot refuse; the full ceremony lives in the commit row block at the top of this file) — and **reconcile BOTH columns, never DELETED alone**; on a PROSE file also run `git diff -- <file> | grep '^+## '`, which names every section you did not author. **Verify a scripted edit FROM THE FILE, never from its own print**; landed means COMMITTED (`git show HEAD:<file> | grep -c <token>`, never a bare `grep <file>`).

⛔ **BEFORE INVESTIGATING A DESTRUCTIVE-LOOKING DELETE COLUMN ON AN APPEND-ONLY FILE, TEST FOR A WHOLE-FILE REFORMAT.** A write-time annotator — this repo expands a bare lesson number into its number-plus-gloss form across a whole file on write — turns a 9-entry append into **+230/-158**, which is exactly the signature the rule above says means destroyed work. **One pass clears it, not a hand read: strip the transform from every deleted line and assert each appears in the ADDED set** (`re.sub(r'\bL(\d+) \([^)]*\)', r'L\1', line)`); `0 unmatched` clears the destruction question, and `added − deleted` must then equal the content you meant to add. Measured twice in one wrap — 230/158 → net 72 = 9 registry entries, and 29/24 → net 5 = 5 gallery rows — both cleared in seconds where a hand read of 158 lines would have cost the rest of the session. ⚠️ **It clears DESTRUCTION only — a foreign line ADDED by the same pass is invisible to it**, so the arithmetic leg is not optional. **TELL: a file you only appended to reports deletions in the hundreds.**

## A LOST UPDATE ALREADY IN HEAD IS INVISIBLE TO EVERY LATER DIFF — BISECT THE VALUE FORWARD AND RESTORE IT AT HEAD

Once a whole-file write has reverted a line that state is in HEAD, so every later commit re-asserts it while producing a genuinely clean numstat, and restoring at the offending commit fixes a state nobody reads.
